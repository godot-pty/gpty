# Add a pane type to gPTY

A pane type is registered in three places (plus tests and docs). Missing any one leaves a pane that spawns from a profile but not the sidebar, or that `check-ffi-surface`/CI rejects.

## 1. Registry and script map

- `godot/scenes/panes/pane_types.gd` — append to `PaneTypes.ALL` **last**: `{"name", "icon", "shortcut", "label_prefix"}`; add `"receives_content": true` only if the pane really accepts routed concept captures (then it appears in the visual editor's target picker).
- `godot/scenes/terminal/terminal_manager.gd` — `_PaneScripts` entry `"<key>": preload("res://scenes/panes/<file>.gd")`.

Palette (`new <display name>`), sidebar buttons, the type-swap menus, and per-type shortcuts all iterate `PaneTypes.ALL`, so nothing else wires them.

## 2. Pane script

`extends PaneBody`, `class_name <Name>Pane`, `_pane_type()` returns the key, `_get_layout_state()` merges type-specific fields, `apply_settings` sanitizes every untrusted value (arrays never go through `PaneBody._set_typed`; handle them explicitly), `_ready` builds the UI. A `.uid` sidecar is generated by the first `--import` — commit it like the other panes'.

If it spawns a program: name the settings `command` (program) + `shell_args` (argv) — the Workspace Trust predicate and consent store (`PaneTypes.tile_spawns_untrusted`, `tile_plan_key`, `TrustedStore`) then cover it with no new clause — and validate at spawn with `pty::validate_program`. Kill the child in `_exit_tree` (and in Rust `Drop`).

If it takes a file/directory path: name the export var **exactly** the settings key (`file_path`, `root_path`, `vault_path`) — `PaneBody._set_typed` only applies a key that names a declared property — keep the typed value when invalid (the settings field keeps the typo; the view shows the reason), validate at use (`is_absolute_path` + `FileAccess.file_exists` / `DirAccess.dir_exists_absolute`), and read through `TextRead.read_prefix` (the shared regular-file gate + 1 MiB cap + torn-UTF8 decode) rather than a second copy.

If it is a companion that should follow a terminal's agent state, implement `agent_state_source_id()` (return the observed terminal's `attachment_id`) and `on_agent_state_changed(state)`: `workspace.gd` dispatches it (primed once when the pane enters the tree, then on every change) and both methods are display-only — never feed a decision, action, capture, or IPC.

## 3. Rust mirrors

- `crates/gpty-core/src/types.rs::PaneType` — variant, `as_str()`, `FromStr`, and `ALL` (bump its length literal, append **last**). Its serde impls delegate to `as_str()`/`parse()`, so the wire spelling **is** the GUI key; `ALL`'s order must equal `PaneTypes.ALL`'s order because `pane_types_match_the_gui_registry_key_for_key` parses the GDScript source and compares them in order.
- `crates/gpty-cli/src/plugin_manifest.rs` — `pane_types()` derives from `PaneType::ALL` (no const to edit); add the key to the expected vector in `pane_type_and_platform_lists_match_the_gui_surface` and update the doc comment that names the GUI count test.

## 4. FFI (only if the pane needs Rust)

New `#[derive(GodotClass)]` in a NEW file under `crates/gpty-gdext/src/`; register it with `mod <file>;` in `lib.rs` (`scripts/check-ffi-surface` attributes each `#[func]` to the class named by its enclosing `#[godot_api]` impl header, so a class may span files — the old "first struct in the file" rule is gone), and keep complex inputs as one JSON `GString` (only `GString`/`bool`/`i64` marshal reliably as input params). GDScript reaches it with `ClassDB.instantiate("<Class>")` + a stale-extension guard (`null` -> status text + `push_error`).

## 5. Tests and docs

- `godot/tests/integration/test_palette.gd` pins `PaneTypes.ALL.size()` (rename the `..._has_six_entries` test to the new count) and each `new <name>` palette entry.
- `godot/tests/integration/test_pane_spawning.gd` pins the type list and label prefixes.
- `godot/tests/unit/test_pane_hardening.gd` if the pane spawns something (trust coverage).
- Unit/integration test for real behavior (`godot/tests/unit/test_<key>.gd` or `integration/`), asserting the observable read API and the visible widget content, not UI wording.
- Live smoke: add a step to `scripts/smoke_pane_api.py` (`new-pane -t <key>` -> require `type == "<key>"`, then `kill-pane`) — the only check that crosses CLI validation -> `NewPaneParams` deserialization (the Rust enum) -> the GUI registry -> `_PaneScripts` on the real socket.
- Docs: `AGENTS.md` (structure tree + Security bullet if it spawns), `godot/README.md` (tree), `crates/gpty-cli/README.md` + `main.rs`'s `pane_type` doc comment if the type is spawnable over IPC, `docs/content/docs/overview/testing.md`, `CHANGELOG.md` (the upcoming release section).

## 6. Gate

`./scripts/ci-check` (fmt, clippy, workspace tests, `check-ffi-surface`, GUT via `gut-check`, live pane-API smoke, audit). New `class_name`s need `godot --headless --path godot --import` before GUT can see them; new GUT files are picked up automatically (gdirs are unit/ + integration/). While iterating, run a scoped test with `godot --headless --path godot -s addons/gut/gut_cmdln.gd -d -gdir=res://tests/unit -gdir=res://tests/integration -gselect=<script_name>` — the bare file stem without `.gd` or a `res://` path (a full path is reported as "Could not find script matching"); one script per run; the authoritative gate stays `./scripts/gut-check`.
