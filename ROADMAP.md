# Roadmap

The source of truth for all `gPTY` features; past, present, and planned.

- GitHub Issues will be used for user-reported bugs and discussions, not roadmap tracking.
- Boundary rules and non-goals live in AGENTS.md under "ADE Architecture Boundary".
- **This file is a queue, not a diary.** Within a release, items are ordered by priority — the first unchecked item is the next thing to work on, so "start the next task" needs no other input. Ordering is: data-loss and correctness first, then security with a reachable path, then the release's own features, then robustness and tests, then low-reachability hardening, then polish, then work that can only happen at release time. Items are never grouped by origin or by which release deferred them (the item text says that where it matters); completed items stay under their release as the record, and the CHANGELOG carries the user-facing summary. A defect or follow-up found while working an item is added here as its own item, in priority position, with enough detail to act on later.

## Future

- [ ] FFI fuzz testing — automated fuzz testing of the terminal grid's binary interface to catch crashes and security issues
- [ ] Inspector / Reasoning follow-ups — host-tools bridge and OpenAI-compatible HTTP still planned. Provider-specific CLI adapters follow the v0.5.2 generic `CliBackend` lane: documented hooks/extensions only, never token reuse or TUI scraping.
- [ ] Dynamic Shaders — GPU shader-based visual effects for terminal backgrounds and overlays (CRT scanlines, glassmorphism, noise)
- [ ] Reactive Environments — ambient visual feedback triggered by concept engine events (e.g., red tint when a test fails, green particles on build success)
- [ ] Instanced-quad renderer (alacritty-style glyph atlas + per-instance color) — evidence-gated: revisit only if render batching plus flood rate-limiting still shows frame-time pain. Godot already GPU-composites the canvas; a full Rust-side texture pipeline is deep custom work (atlas management, eviction, per-cell truecolor uploads) for a small incremental gain.
- [ ] Shared graph nodes (free DAG) — the visual editor's rules are chains because a compiled entry's identity is the trigger's name: one trigger = one rule, and a shared condition or action would compile two entries under one name. Fan-in/fan-out needs OR'd triggers (`triggers: [regex…]`) and a rule id independent of the trigger name in the vocabulary. Deferred from v0.5.4 — revisit with demand evidence, not before.
## v1.0.0 — Public Launch

Launch is deferred: `gPTY` stays below 1.0.0 until either the project gains a growing, active userbase or the 0.x feature-set is exhausted — code signing and broad distribution are only worth pursuing once one of those is true.

- [ ] Distribution — install.sh, Homebrew tap, AUR, winget (promoted from Future: launch blockers), and GitHub releases.
- [ ] Code signing — macOS notarization + Windows Authenticode (promoted from Future: SmartScreen/Gatekeeper warnings are launch-killers).
- [ ] Docs — agent guide, plugin authoring guide, socket API reference (from the existing schema generator), 60-second quick start.
- [ ] Community infrastructure — plugin registry live, examples repo, community channel.
- [ ] Launch criteria — first-class agent adapters, example plugins, the reference workflow demo (agent runs tests in a pane while the user watches in the GUI), and a working headless reattach story — all verified before the public launch post.

## v0.7.0 — Media Pane

- [ ] Media pane type — `media` in `PaneTypes.ALL`; plays local audio/video from an absolute file path validated by `sanitize_tile` (same trust rule as code_viewer/file_tree). Remote/URL streaming deferred — a separate trust boundary.
- [ ] Rust media backend — demux/decode in Rust: `symphonia` for audio; video decoding via pure-Rust codec crates or `ffmpeg` bindings (license review at design time: LGPL build vs pure-Rust). Output is packed flat arrays of decoded frames/samples — the same FFI packing pattern as the terminal grid.
- [ ] Video rendering — decoded frames uploaded as `ImageTexture` in GDScript; bounded frame queue so a high-bitrate stream cannot stall the UI thread (same discipline as PTY flood rate-limiting).
- [ ] Audio playback — decoded PCM streamed into Godot `AudioStreamGenerator`; A/V sync against the Godot clock; volume/mute controls.
- [ ] Playback controls — play/pause/seek/loop per pane; transport state surfaced through the existing `paneStatus` primitives.
- [ ] Format matrix — MP4/WebM/MKV containers, H.264/H.265/VP9/AV1 video, MP3/FLAC/Ogg/Opus audio; codec support documented per platform.
- [ ] Media security notes in AGENTS.md — media files are untrusted input: memory-safe/audited decoders only (the concept-engine ReDoS stance extended to codec parsing), demux/decode size caps, no sandboxing claims (plugin trust-model language).
- [ ] Standalone by design — ships alone with no dependency on or coupling with any other feature, so its A/V infrastructure risk gates nothing else.

## v0.5.5 — Plugin Ecosystem

- [ ] User-owned pane environment — a file must not carry env. Restore ignores a tile's `shell_env`, and per-pane env becomes a property the *user* grants: an app-written map keyed by `attachment_id` (`user://pane_env.json`, written only by the pane settings UI, never by profiles/workspaces), so a pane's env still survives restarts while no file can supply one. Profiles lose the ability to carry env by design (documented; a profile that needs it points at shell rc or asks the user to set it once). Companion fix: `_restore_into` currently applies tile settings *before* `apply_to_terminal`, which overwrites `shell_env` with the user's global — so per-pane env is silently discarded on restore (a bug) and no file-supplied env reaches a child (an accident, not a control). Fix the ordering only together with this item, or files regain env authority. Migration: restored tiles' env is dropped with a notice listing what was dropped — do NOT auto-adopt it into the store, since that would launder a hostile file's payload into the trusted map. `BLOCKED_ENV_KEYS` stops growing: it becomes the floor for user-authored, ambient, and plugin-supplied env instead of the primary defense, and the plugin lane may carry env in a manifest only behind the plugin review dialog. Rationale — env is spawn-time authority, not display config: module search paths (`PYTHONPATH`, `NODE_PATH`, `RUBYLIB`, `LUA_PATH`, `CLASSPATH`), build-tool override (`RUSTFLAGS`, `GOFLAGS`, `CC`, `LD`, `MAKEFLAGS`), git config-by-env (`GIT_CONFIG_GLOBAL`, `GIT_CONFIG_COUNT`/`_KEY_n` → `core.pager`, `alias.*=!cmd`, `core.sshCommand`), credential/agent hijack (`SSH_ASKPASS`, `SSH_AUTH_SOCK`), traffic redirection (`HTTPS_PROXY`, `SSL_CERT_FILE`, `PIP_INDEX_URL`, `NPM_CONFIG_REGISTRY`, `KUBECONFIG`, `DOCKER_HOST`), and credential helpers or agent sockets (`SSH_ASKPASS`, `SUDO_ASKPASS`, `SSH_AUTH_SOCK`, `KRB5CCNAME`, `GPG_AGENT_INFO`). The second pass also found the sanitizer's own gaps: `LD_DEBUG`/`GLIBC_TUNABLES`, `HOME`/`XDG_CONFIG_HOME` (a redirected HOME sources different rc files), `GIT_CONFIG_SYSTEM`, `GIT_DIR`/`GIT_WORK_TREE`, and no cap on the key set past the 64-line window. An enumerated blocklist cannot converge on a class like that. Decided over the cheaper alternative (D: stop persisting per-pane env entirely) because C keeps the user's own env across restarts.
- [ ] Plugin manifest — `gpty-plugin.toml` (id, name, version, min_gpty_version, platforms, build/startup commands, actions, events, link handlers) plus gpty-native `[[concepts]]` and `[[profiles]]` sections so a plugin can be pure JSON — zero code.
- [ ] Plugin install & lifecycle — `gpty plugin install <owner>/<repo>@ref` (clone, manifest validation with size/count/path caps, review dialog reusing the Workspace Trust pattern, pinned revision, per-plugin log dir) and `list` / `enable` / `disable` / `run` / `logs`. The entire CLI is the plugin API (`GPTY_BIN_PATH`); commands are argv arrays, never shell-evaluated.
- [ ] `cli_view` pane — runs a command and streams stdout into a pane body: plugin UI v1 without a Godot SDK. Native third-party GDScript/Rust pane plugins deferred to a future SDK (`PaneTypes.ALL` is the layout-trust anchor; see AGENTS.md).
- [ ] Pane contract extension — `on_agent_state_changed(state)` in `PaneBody` for custom panes.
- [ ] Plugin registry — JSON index repo + browse page on the docs site; submission by PR.
- [ ] God-object split — continue splitting `workspace.gd` (~1350 lines) / `terminal_pane.gd` / `terminal_manager.gd` into focused files (workspaces block, persistence, polling, palette, profile/layout restore). IPC dispatch (`ipc_handlers.gd`) and window chrome (`window_chrome.gd`) were already extracted in v0.5.1; concept routing lives in `concept_router.gd`. Do it alongside the plugin work, which touches `workspace.gd` heavily. Two specific seams first: the duplicated enabled-concept filter (`ConceptManager._push_to_rust` vs `workspace.gd._push_concepts_to_engine` — the same defect had to be fixed twice, and only one copy is reached on each path) collapsing to one entry point; and the `GptyTerminal` `#[func]` surface (~38 exports on one class) splitting into grid/capture/IPC facets, since a plugin author otherwise has to reason about all of it to touch any of it.
## v0.5.4 — Visual Concept Graph

- [x] Visual Concept Graph — a full-window GraphEdit overlay (Settings → Concepts → "Open Visual Editor") authors rules as chains: trigger → condition* → action (capture & route, or notify only); ports hold one wire, so a rule cannot fork or merge. New vocabulary: `conditions: [regex, …]` — ANDed with the trigger on the same line, capped at 8 × 1024 bytes, and a malformed condition rejects the whole concept (dropping one would widen matching); `GptyTerminal.validate_regex()` exposes the engine dialect so the editor cannot author a regex GDScript's PCRE2 accepts but the Rust engine silently discards. `ConceptGraphModel` (pure, unit-tested) builds the canvas from merged concepts, compiles it back, writes a rule equal to its shipped default as *no* user entry (defaults keep tracking updates), tombstones a deleted shipped rule exactly like the manual dialog, and keeps content-invalid rules as drafts with an error instead of compiling them. The `graph` sibling key in `user://concepts.json` holds layout only (sanitized positions + draft nodes), so `concepts` stays the single content store and a manual-dialog edit cannot drift; the compiled key set is closed (`entry_for_path`), so a node cannot smuggle a legacy `cmd` back in. Verified: 9 new engine condition tests, 23 model unit tests (canvas/validation/compile/tombstones/drafts/layout), 394/394 GUT, full `ci-check`; live smoke against the real GUI + GDExtension (open → splice a condition through the connection handlers → save → only the edited rule written → engine readback holds the condition; 4/4 edges rendered as connections, zero auto-layout overlaps, screenshot inspected). Two defects found and fixed by that live pass: rebuilding the canvas removed GraphEdit's internal children (`connections_layer is missing`), and auto-layout spacing let the action overlap a condition.
- [x] Pixel-smooth divider drag — shipped the pixel-geometry approach, not the finer-grid one (which still relayouts every step and still snaps the *content* per step): while a divider is dragged, the tiles on the line move their wrappers by the raw pixel delta (the far side grows, the near side shifts) with no tile mutation and no `tiles_resized` per motion, so nothing reflows until the release. The press snapshots the line's tiles, their committed offsets, one unit in pixels, and the unit travel limits, so `MIN_TILE` and the grid edges are enforced mid-drag in pixels and the preview can never show a position the commit refuses; the release rounds the previewed travel to whole units, applies it to the tile model, relayouts once, and the pane's own `RESIZE_DEBOUNCE` settles the terminal content. The preview is absolute from the press (backtracking restores the layout), and an edge with no tile on its far side — the window border — no longer starts a phantom drag. Verified: 16 GUT drag tests including the new invariants (motion leaves the tile model untouched, exactly one `tiles_resized` per drag, the preview clamps at `MIN_TILE`, backtracking commits nothing, border edges are inert); full `ci-check`; live run at 29 px/unit — a 40 px drag previewed the divider to 910 px (31.38 units, deliberately off a boundary) with the model untouched, then committed span 30→31 at 899 px (11 px snap, within half a unit); mid-drag screenshot inspected for gaps/overlap.
- [x] Pane file sinks — the code viewer now reads through a type gate and a cap. `FileAccess.file_exists` is Godot's regular-file check (measured: false for directories, `/dev/zero`, FIFOs and even symlinks to FIFOs; true for regular files and symlinks to them) and `get_size` is -1 for anything non-regular, so non-regular paths are refused before `open` — the "never-EOF device hang" the first pass asserted is not reachable through this sink (a FIFO `open` returns null without blocking); the real hazard was the unbounded read, now capped at `MAX_FILE_BYTES` (1 MiB) with a visible truncation notice and a hand-rolled UTF-8 cut so a sequence torn by the cap is dropped instead of rendered as U+FFFD. The file tree asks for confirmation before `OS.shell_open`, showing the exact path, and refuses non-absolute and non-regular paths (scheme allowlist: only an absolute local path becomes the `file://` URI the sink constructs itself — a downloaded `.desktop` file would otherwise be *run* by the mime handler). Bonus defect found while testing: `CodeEdit.add_comment_string` does not exist on Godot 4 — the call raised a script error that aborted `load_file` before `_refresh_view()` for `.rs/.gd/.py/.c` files, leaving the pane on the previous file's view; now `add_comment_delimiter` (with a regression assertion on the view toggle). Verified: 7 new GUT tests (full/truncated/torn-UTF-8 loads, directory refusal, tree confirmation, directory expansion without a dialog, non-absolute refusal), full `ci-check`; live run — a 5 MiB file rendered 1,048,632 chars with the notice, a FIFO path returned in 3 ms and left the pane empty, and the tree's confirmation dialog was screenshot-verified. (Deferred from v0.5.3.)
- [x] Pin the GDExtension on Windows — `pin_library()` now has a `cfg(windows)` branch calling `GetModuleHandleExW` with `GET_MODULE_HANDLE_EX_FLAG_PIN | GET_MODULE_HANDLE_EX_FLAG_FROM_ADDRESS`, naming the module by the address of the function itself (nothing depends on the DLL's file name) and reporting a failure through the `log` bridge instead of failing silently; the `libc`/`RTLD_NODELETE` branch is unchanged, the call site is unconditional, and a no-op stub covers platforms with neither loader. Raw `extern "system"` + `#[link(name = "kernel32")]` rather than a new `windows-sys` dependency. Verified by compile: `cargo check --workspace --target x86_64-pc-windows-msvc` under `-Dwarnings` passes locally through `ci-check`'s xwin/clang-cl step (the same target and flags as the CI `rust-windows` job). Runtime is still unverified — the Windows smoke item below is what will exercise the pin at exit.

- [x] Event-channel hygiene — (a) subscriptions no longer leak: `SUBSCRIPTION_IDLE` (120 s without an `eventsPoll`) releases the slot and its queued events on the next subscribe/emit, so the 64-slot cap cannot be exhausted by abandoned clients; unit-tested in both directions (a stale slot is released, a freshly-polled one survives) and end-to-end (a subscribe at the cap reuses an abandoned slot instead of failing). GUT: a 30-delta burst leaves the view unrendered until the debounce, then shows the whole turn. (c) The OMP translation boundary is a per-event **field allowlist** (`ALLOWED_FIELDS`, built field-by-field with caps) instead of a rename-and-pass-through, so prompts, answers, tool arguments/results or any future extension field cannot ride along; unit-tested with a hostile payload (forbidden fields dropped, wrong types and over-cap values dropped, unknown events rejected). Live probe against the real socket: subscribe/poll round-trip, wrong capability → `-32001`, oversized `thinking` text → `-32602`, and a `tool.finished` carrying `prompt`/`tool_args`/`answer` was accepted, translated and delivered — the allowlisted `is_error` set the terminal's Tier 1 state to `needs-attention`. (Deferred from v0.5.3.)
- [x] GUT aborts can pass CI — the gate is now `scripts/gut-check`, which owns the GUT command (`ci-check` and the `gut-tests` CI job call it, so the run and its guard cannot drift) and judges the output instead of the process exit code: Godot parse/script-error lines fail it, the Run Summary must be present and end in `All tests passed!`, the script count it reports must equal the `test_*.gd` files the gdirs hold, and every collected script must contribute at least one test. A `test_*.gd` nested below a gdir is listed as never-run, because GUT does not recurse (`include_subdirectories` is off) — a suite that quietly stops covering a directory is the same failure class. Reproduced before the fix: a parse error in one collected script made GUT break into Godot's debugger, run 4 of 40 scripts, print no Run Summary, and exit 0 in 1.3 s (the live run takes 57 s) — the old step printed PASS off that exit code. Verified after: the clean run reports `40 scripts, 406 tests, all passed` and exits 0; the same probe exits 1 with both parse-error lines plus "no Run Summary in the output — the run stopped before it finished"; a `test_*.gd` that does not extend `GutTest` and a nested `test_*.gd` each fail with the offending file named and the file counts it contradicts. CONTRIBUTING and `docs/content/docs/overview/testing.md` now point at the script; AGENTS.md's Testing section records why the raw command is not the gate.
- [x] Seam contract tests — each of the three named seams now has a test that reads *both* sides instead of a copy of one side (the `#[func]` surface it starts from was already enforced by `scripts/check-ffi-surface`, which `ci-check` runs). (a) **MCP tool → IPC method → dispatch**: `crates/gpty-cli/src/commands/mcp.rs` no longer carries a hand-written method list; it parses the real registrations out of `crates/gpty-gdext/src/ipc.rs`, the real dispatch arms out of `ipc_handlers.gd`, the `method ==` requests `workspace.gd` intercepts before dispatching (`paneWait`), and every `client.call`/`call_and_format` literal under `src/commands/`, then asserts one vocabulary with the advertised MCP tools. It found the drift it was written for: `paneWait` was registered but missing from the dispatcher (handled in the workspace's per-frame loop, which the test now models) and `version`/`shutdown` carried dead GDScript arms for two methods the Rust server answers locally — both arms deleted, so the partition is exact (registered = locally answered ⊎ GDScript-handled) and every registered method must be named by a CLI call site. (b) **Pane targeting by id and legacy label**: the old `godot/tests/unit/test_ipc_routing.gd` reimplemented `_find_pane_by_label`, the `listPanes` response and the error envelope inside the test and asserted on those copies (its own header admitted it), so it could not fail when the shipped handlers changed; it is deleted, and `godot/tests/integration/test_ipc_dispatch_contract.gd` drives `WorkspaceIpcHandlers.handle` against a real `Workspace` — every id `listPanes` reports must address the pane IPC resolves, a `T<n>` label must land on the labelled pane, terminal-only methods (`paneRead`, `inject`) must refuse a non-terminal, an unknown method answers -32601, and `layoutLoad` must refuse an untrusted profile while restoring a trusted one. Docs: `docs/content/docs/overview/testing.md` no longer claims `Workspace` cannot be instantiated headless (three test files do) or that real PTY spawning is `#[ignore]` (nothing is); AGENTS.md records the seam-test rule and `activate_pane`.
- [x] Concept matching under flood — measured first, and the answer was *not* a cap. The cost is lines × concepts × regex, and the per-concept loop paid each regex's own prologue on every line (~20 ns per concept), so a 128-concept library spent 2.7 µs on a line that matched nothing. The new probe (`cargo run --release -p gpty-core --example concept_probe`, kept, with its results recorded in the header) flooded a real pane: ~1 KiB lines ran at 79.9 MB/s with no concepts, 79.7 with the shipped set, 53.0 with 128 typical triggers and **5.8** at the parser's ceiling (128 concepts × 1024-byte trigger × 8 × 1024-byte conditions); 30-byte lines ran at 47.3 MB/s with no concepts and 8.6 with 128 typical triggers — a flooded pane lost up to 90 % of its throughput to matching. Fix: `ConceptMatcher` puts **one combined `RegexSet` pass** in front of the per-concept loop, so the common case (nothing matches) never pays the per-concept multiplier and only a gate hit runs the ordered loop that decides capture-vs-notify — conditions and precedence unchanged, and `matcher_agrees_with_match_line_on_every_pair` pins the equivalence across condition-fails, disabled, notify and capture cases (a gate built from triggers alone is exactly where a verdict could have changed). After: 81.1 MB/s with the default set, 73.9 with 128 typical triggers, **73.3** at the ceiling (12.6×), and 44.9 on 30-byte lines with 128 typical triggers (5.2×) — the worst case is now within ~10 % of no concepts at all. No match-rate cap: dropping matches under load would silently break the feature's contract, the parse caps already bound the per-line work, and matching runs inside the pane's own task (one core, never the UI thread). Per line the gate is 44× cheaper at 30 B/128 concepts and 128× at the ceiling's worst case; a single-concept set pays ~2 ns more per short line for the combined pass (17 → 19 ns) and compiling the gate costs 0.2/3.6/27 ms for the shipped/typical-128/ceiling sets at `set_concepts`. Two adjacent fixes in the same path: the engine takes the concept read lock once per output batch instead of once per line, and a poisoned `RwLock` now follows the `Mutex` policy (skip the work, report the first occurrence) via `lock::read_or_warn`/`write_or_warn` instead of panicking the pane's task.
- [x] Windows runtime smoke — the `windows-smoke` job (`windows-latest`) now boots the GUI headless and drives the CLI against it: the CLI and the GDExtension are built for Windows, Godot 4.7.2's Windows editor is downloaded with its SHA512 pinned from the release's `SHA512-SUMS.txt`, and `scripts/smoke_pane_api.py` — one harness for every platform, since only the transport differs (Unix socket vs named pipe, `open()` on both) — runs the full flow: control-pipe round trip, the **named-pipe event listener** (`subscribe`/`eventsPoll`, spawn and killed events), pane lifecycle, inject → pane-wait → pane-read, scrollback, broadcast, `pane-run` exit code, kill-pane. GUT stayed Linux-only at that point (`cfg_shell_command = "/bin/sh"` in the suite); it runs on Windows now — see the next item. Writing the job surfaced two real Windows defects, both fixed here: the first-run shell default was `/bin/bash` everywhere, which `validate_executable` refuses on Windows (not absolute there) so **every pane of a fresh Windows install failed to start** — the default is now `%COMSPEC%` (falling back to `cmd.exe`) through `SettingsManager.default_shell_command()`; and `pane-run` always passed `-c`, which `cmd.exe` rejects — `PaneTypes.shell_run_args()` now picks `/c` for the cmd family and `-c` otherwise (unit-tested; `pane-run` on Linux is unaffected). The harness itself is verified on Linux (full PASS, and `GODOT=/bin/true` reports `FAIL [launch]` with the log tail, exit 1); the Windows leg is observed by CI, which is the point of the job. `ci-check` step 5.5 runs the same file with `python3`, and the bash smoke + its Unix-only event client are gone.

- [x] History store write path — `TermGrid::store_line` called `HistoryStore::append` per output line while holding the grid mutex, so a flooding pane held the lock the UI renders under for ~30 µs per line and was itself capped at 33 k lines/s (a `yes` pane moved 1 MB/s), and the store had no byte cap — 10 000 rows of 16 KiB lines is 160 MB of SQLite and FTS index. Now a pane owns a `PaneHistory`: `push` queues the line (no lock, no SQLite on the terminal path) and a per-pane writer thread commits batches — a batch grows to `FLUSH_ROWS` (512) or commits after `FLUSH_INTERVAL` (200 ms) of quiet, then trims the store. - [x] Trust gate on the IPC restore path — `ipc_handlers.gd` `layoutLoad` called `ws._do_activate(profile)` directly while the gate lived in `_activate_profile`, so `gpty layout load <name>` and the `layout-load` MCP tool restore an untrusted profile with no consent step. An untrusted profile is now refused over IPC with an error pointing at the GUI; verified live against a running GUI.
- [x] Inspector prompt fence — `gpty-ai/src/prompt.rs` wrapped untrusted capture in a literal ``` fence with no escaping and interpolates `concept_name`/`source_pane` raw, so a capture containing a fence escapes the data block (omp-only, tool-free backend, so display-level). The fence now outgrows the longest backtick run in the capture (capped at 32) and metadata is flattened to one line.
- [x] A notify-only match must not shadow a capture — `concept::match_line` returned the first match and `apply_match` starts nothing for `SingleLine`, so a broad notify-only concept placed ahead of a capture concept silently suppresses that capture. Precedence is now explicit: capture outranks notify, first match wins within a class.
- [x] Finalize an in-flight capture when a pane is dropped — `SpawnedTerminal::drop` called `task.abort()`, so the documented finalize-on-close path never ran: closing, swapping, or resetting a pane mid-capture silently lost the capture instead of routing it (and a capture the task had already finalized was stranded, because nothing polls a dead pane's queue). The capture state machine is now shared (`Arc<Mutex<..>>` behind the same `CaptureSession` API) so `Drop` can finalize what the task still held, and both it and any finalized-but-undrained event go to an engine-level orphan queue that GDScript drains each frame and routes through `ConceptRouter.route_orphaned_capture` (delivery only — the source terminal, its grid, and its raw-byte store are gone). The dead `spawn_pty_terminal` path is removed with it.
- [x] Post-resize suppression while capturing — the post-SIGWINCH window was consulted only in the non-capturing branch, so redraw bytes were buffered into the capture, routed as output, and consumed the 4 MiB budget. An active capture now drops bytes printed inside the window (feeding the frozen grid instead would paint the repaint onto content it never had); output after the window is captured normally. `post_resize_window_is_not_buffered_into_a_capture` pins both sides of the boundary.
- [x] Position-swap popup re-resolves its targets — `show_position_swap_popup` captured tile indices when it opened, so a pane killed meanwhile (IPC `killPane`) swapped the wrong pair or indexed past the end with no indication. Rows now carry the pane itself and are resolved by identity against the current tile list at click time; a pane that is gone cancels the swap with a toast. `_tile_index_of` replaces the three duplicated index lookups, and 2 GUT cases cover the shifted pair and the closed target.
- [x] Restored-executable parent-directory check — `pty::validate_executable` stats the program file only. A binary whose own mode is safe (0755) can still be swapped by another user when it sits in a group/other-writable directory without the sticky bit; `/tmp` is protected by default, other shared directories are not. Walk the parent chain and reject when any directory is writable by others without `+t`, then extend the existing test.
- [x] Parallel test job in CI — `scripts/ci-check` ran only `cargo test --test-threads=1`, and that serialisation hid a shared-static isolation bug in `crates/gpty-gdext/src/ipc.rs` until a multi-threaded run surfaced it; step 4.2 now runs the workspace suite with default parallelism as well. The intermittent failures it was left open for turned out to be five distinct causes, all fixed here: (1) a pane's exit code was probed once when the pty read side closed, and a child that closes its fds a moment before it is reapable answers that probe with `None` — `paneStatus`/`paneRun` then reported no exit code at all (now polled briefly); (2) the OMP session's liveness probe has the same window, so the next prompt could land in a closed pipe and fail the turn (now re-spawned and re-served); (3) two OMP tests share the process-global `GPTY_OMP` and clobbered each other under the default parallel runner (now serialised by a test lock — found by the new test added with this work); (4) `fake_adapter` reused temp-script paths across runs, so a leftover child from a killed run made `exec` fail with ETXTBSY (paths now carry a run-unique suffix); (5) the pty tests' wall-clock budgets assumed an idle machine and reported product bugs under load (now a shared `wait_until` / longer drains). Result: 12/12 clean `cargo test --workspace` runs on the development machine, where the suite previously failed roughly one run in eight.

## v0.1.0 — Core Engine

- [x] Multi-PTY terminal emulator — spawn and manage multiple shell sessions in a tiling grid. Each session is an independent PTY with its own shell process, environment, and working directory.
- [x] Tiling grid layout — split panes horizontally or vertically, resize by dragging splitter handles. Built on a Rust tile layout engine that enforces minimum pane dimensions and redistributes space when panes are added or removed.
- [x] ANSI/vte parsing — full SGR color and cursor positioning via alacritty_terminal. Handles 16-color, 256-color, and true color (24-bit) sequences. Strips escape sequences for concept matching.
- [x] Concept engine — regex-based trigger/action matching with label routing. Every line of PTY output is tested against registered concept patterns. Matching lines broadcast events on a pub-sub channel; panes with matching labels execute the associated action. (Command execution removed in v0.5.3 — concepts are capture-and-route only.)
- [x] SingleLine capture mode — each matching line triggers an event on the pub-sub channel. Receiving panes inject the action's command template into their PTY stdin, enabling cross-pane automation. (The mode and its injection path were removed in v0.5.3; it never delivered an action before then — labels were always empty and every pane shared id 1.)
- [x] Settings persistence — font size, cursor shape, window mode, and other preferences saved to `user://settings.json`. Settings auto-load on startup and auto-save on change via a debounced save timer.
- [x] Phosphor icon set — 100+ icons for toolbar, sidebar, and pane action buttons. Unicode PUA codepoints rendered via the bundled Phosphor Regular font. Icons are exposed as `const` strings in `icons.gd`.
- [x] Sidebar with pane list — collapsible left panel showing all tiles with focus, kill, minimize, and swap buttons per pane. Also exposes window mode toggle and per-pane-type spawn buttons.
- [x] Control-based renderer — terminal grid drawn in GDScript via `_draw()`. Rust packs cell data (chars, foreground, background, attributes) into flat arrays; GDScript unpacks and renders them line-by-line with damage tracking for incremental updates.
