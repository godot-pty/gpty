The roadmap is a prioritized queue split into one page per release chain under `docs/content/docs/roadmap/` (`v0.1.md` … `v1.0.md`, then `future.md`). `ROADMAP.md` is the root index, and `docs/content/docs/roadmap/_index.md` renders it on the site.

Detailed execution of roadmap tasks is guided by `skill://gpty-roadmap-task` (body at `.omp/skills/gpty-roadmap-task/SKILL.md`).

## Core Principles

- **The queue is the priority:** Within a release, row order *is* the priority, and the first unchecked row (⬜) in the earliest unfinished release is the answer to "what's next".
- **Release chain order:** Open chain pages in version order, take the first chain that still has a ⬜, and take the first ⬜ on that page. An earlier release with a leftover ⬜ always precedes a later one. Future is never picked from.
- **No separate grouping:** No grouping by origin or carry-over headings. Finished rows stay in place with evidence, and the changelog carries the user-facing release notes.

## Row Format

Every row is exactly one line in the release table:

```markdown
| ✅ or ⬜ | AREA | **Title** - evidence, fix, tests |
```

- **Status:** `⬜` for open, `✅` for completed.
- **Area:** Exactly one of `TERM`, `GUI`, `IPC`, `CLI`, `SEC`, `PLUGIN`, `WIKI`, `CONCEPT`, `MEDIA`, `AGENT`, `CORE`, `BUILD`, `DOCS`, `PROJECT`.
- **Title:** Unique across all release chains in bold (`**Title**`), followed by ` - ` and the actionable description.
- **Escapes:** Escape literal pipes in cells as `\|`, and enclose `<` inside backticks to prevent raw HTML stripping.

## Priority Ordering Rules

When adding or re-prioritizing rows, follow this strict precedence:

1. **Data-loss and correctness:** Bugs causing data corruption, accidental deletion, or broken core behavior.
2. **Security with reachable path:** Exploitable or exposed security defects.
3. **Release headline features:** The primary differentiating features scoped for the release.
4. **Robustness and automated tests:** Flake fixes, test coverage, race elimination.
5. **Low-reachability hardening:** Defense-in-depth and static verifications.
6. **Polish and aesthetics:** Visual consistency, theme alignment, copy improvements.
7. **Release-time tasks:** Packaging, tagging, and deployment verification.

Ties break toward the smaller item.

## Defect and Follow-up Tracking

- **No silent fixes:** A defect or follow-up discovered while working on a task is never fixed silently, queued in a comment, or folded into an unrelated commit.
- **Add to queue:** Add it as its own row in the appropriate release in priority position, with the evidence that makes it actionable (failure observation, code location, proposed fix).
- **Folded details:** If a triage note, correction, or clarification exists for a row, update that row's text directly rather than adding a separate "corrections" row.

## Evidence Screenshots

Images in `docs/static/images/` follow specific naming conventions:

- **Release screenshots:** Named `v<version>_<n>.png` (generated by `scripts/screenshot-gpty`).
- **Roadmap evidence:** Named `issue-v<build>-<slug>.png` (`<build>` is the build version where the capture was made).
- **Placement:** Never embed an image inside a table row. Place screenshots under a `## Screenshots` section at the bottom of the chain page with a bold caption explaining numbered callouts, and reference the caption from the row.

## Closing a Row

1. Flip `⬜` to `✅` in place.
2. Update the row text to describe what shipped, concrete measured metrics, and passing regression test names.
3. If the row closed a bug, ensure the commit carries a `Cause: <class>` trailer matching [Defect classes](defect-classes.md).
4. Run `python3 scripts/docs-check` and `./scripts/build-docs` to ensure synchronization.

## Adding a Release Chain

1. Create `docs/content/docs/roadmap/<slug>.md` with front matter (`title`, `weight` incremented from previous chain).
2. Add a brief paragraph summarizing what the release chain achieves.
3. Add `## vX.Y.Z - Name` sections with three-column tables.
4. Link the new chain page from `ROADMAP.md` as `docs/content/docs/roadmap/<slug>.md`.
