Two releases that came out of the October 2026 assessments. v0.8.0 is the UI/UX overhaul: shared theme and type scale, readable settings, empty states, small-window behaviour, the command palette and dialogs. v0.8.1 is terminal fidelity: the user's own shell, drawn text attributes, box and braille characters, fonts, terminal queries, OSC 7 and OSC 52, and the modern TUI protocol set.

| ⬜ | GUI | **Resizing a pane is smooth: the resize cursor always shows, no gray band while dragging, no hop on release** - three separate defects found together in the October 2026 usability pass, all reproduced against the v0.7.0 code. (1) *The resize cursor goes missing after a drag.* Verified: after dragging any divider, the cursor stays an arrow over some of the strips (on both axes) although the viewport's hover target is correct, and it comes back after a click in any pane. Cause: while a drag is active `Workspace._input` consumes every mouse event with `set_input_as_handled()`, including the button release, so the viewport never sees the release of the press the edge strip started. Its mouse-focus state stays stale and it stops updating the cursor shape until some other press-and-release pair reaches it. Fix: end the drag on the release but let the release continue to the GUI, consuming only the motion (verified in a scripted run through `Viewport.push_input`: with that change the cursor is correct over every strip after the drag). The release reaches only the strip that took the press, and `end_edge_drag` is already a no-op by then. (2) *A gray band shows while dragging.* Verified from captured frames: a terminal fills its whole rectangle with `default_bg`, `Color(0.12, 0.12, 0.12)`, while its cells use the engine's own default background (black, with no colour scheme selected), so the area the pane has grown into shows `(31,31,31)` beside `(0,0,0)` cells. The grid only reflows after `RESIZE_DEBOUNCE` (50 ms) with no further size change, which never happens mid-drag, and the old grid stays centred in the new rectangle until then. Fix: fill with the same colour the cells use (the engine's default background, or the selected scheme's), so the margin is invisible; and replace the quiet-period debounce with a throttle while a drag is active (about 10 reflows a second, one final reflow on release), so the text follows the divider the way other terminals do, without a window-size signal to the shell on every motion event. (3) *The divider hops on release.* The preview follows the pointer in pixels and the release rounds to one of 60 grid units, up to half a unit away, about 13 to 16 px across a 1920 px window. Fix: round the preview to units while dragging, so what is shown is what is committed. Also in this item: the strips are 6 px wide inside a 1 px border on each pane, so a divider has a 2 px dead band between two strips and a 14 px target in all. Replace the per-pane strips with one handle per divider line, wider than that and without the dead band, with a hover highlight on the divider, which stays visible even where the platform's cursor fails to change. Tests: a viewport-driven GUT test that presses, moves and releases and asserts the strip received the release and that no drag state is left behind; a frame-capture test that no pixel in the exposed margin differs from the cell background during a scripted drag (a magenta sentinel behind the grid also proves that no gap opens between panes); a preview-equals-commit assertion; and a manual check of the cursor on a windowed run, since the headless display driver has no cursor. |

Probes run against a sandboxed v0.6.0 build (commit `b8bf5f9`) with the same synthetic-input + viewport-capture method as the UX audit (AGENTS.md, "UI/UX assessment method"), plus a read of the emulator's event path in `crates/gpty-core/src/term.rs`. The theme: gPTY's differentiator is its control surface, but a daily driver is judged first on whether `htop`, `nvim`, `lazygit` and `ssh` look and behave right, inside the user's own shell. Almost everything here is something the emulator already knows, or the OS already told us, and gPTY drops - or a wrong default that hides it. The release sits **after** v0.8.0 (the theme work, so the fidelity fixes are not themed twice) and deliberately **before** v0.9.0: the grid wire protocol reuses `TermGrid`'s packed flat arrays as the wire format, and the cell carries no strikeout/dim/undercurl bits today, so widening it after the format is frozen is a protocol revision, while before it is a struct change. Boundary rules hold throughout (AGENTS.md "ADE Architecture Boundary"): everything here observes and displays; nothing interprets terminal output into an action, every terminal reply stays a fixed template, and every new OSC consumer is bounded, sanitised and display-only unless its item says otherwise.
