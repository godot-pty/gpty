Two releases that came out of the October 2026 assessments. v0.8.0 is the UI/UX overhaul: shared theme and type scale, readable settings, empty states, small-window behaviour, the command palette and dialogs. v0.8.1 is terminal fidelity: the user's own shell, drawn text attributes, box and braille characters, fonts, terminal queries, OSC 7 and OSC 52, and the modern TUI protocol set.

## v0.8.1 - Terminal Fidelity

Probes run against a sandboxed v0.6.0 build (commit `b8bf5f9`) with the same synthetic-input + viewport-capture method as the UX audit (AGENTS.md, "UI/UX assessment method"), plus a read of the emulator's event path in `crates/gpty-core/src/term.rs`. Each item is marked verified (reproduced in the running app), code (read in the source, not run) or not tested. The probe scripts are scratch files and are not committed - the "Fidelity regression suite" item below turns them into one. The theme: gPTY's differentiator is its control surface, but a daily driver is judged first on whether `htop`, `nvim`, `lazygit` and `ssh` look and behave right, inside the user's own shell. Almost everything here is something the emulator already knows, or the OS already told us, and gPTY drops - or a wrong default that hides it. The release sits **after** v0.8.0 (the theme work, so the fidelity fixes are not themed twice) and deliberately **before** v0.9.0: the grid wire protocol reuses `TermGrid`'s packed flat arrays as the wire format, and the cell carries no strikeout/dim/undercurl bits today, so widening it after the format is frozen is a protocol revision, while before it is a struct change. Boundary rules hold throughout (AGENTS.md "ADE Architecture Boundary"): everything here observes and displays; nothing interprets terminal output into an action, every terminal reply stays a fixed template, and every new OSC consumer is bounded, sanitised and display-only unless its item says otherwise.

| Done | Area | Item |
|:---:|:---:|---|
| ⬜ | TERM | **The default shell is the user's shell, not `/bin/bash`** - verified: on a machine whose login shell is `/bin/fish` (`$SHELL` and `getent passwd` agree), every pane ran `bash` (`ps -p $$ -o comm=`), so the user's prompt, aliases and plugins were missing with no hint why. `SettingsManager.default_shell_command()` returns the literal `/bin/bash` on every non-Windows platform; on Windows it returns `%COMSPEC%`, i.e. `cmd.exe`, which is not what a Windows user opens a terminal for. Fix: resolve the fresh-install default from `$SHELL`, validated by the same rule `validate_executable` applies (absolute path, regular executable file), falling back to `/bin/bash` then `/bin/sh`; on Windows prefer `pwsh.exe`, then `powershell.exe`, then `%COMSPEC%`, found by absolute path. Settings → Terminal lists the detected shells (including installed WSL distributions) as choices beside the free-text path, and shows what the default resolved to. A saved `shell_command` is never overwritten. Two knock-on points to handle in the same item: the GUT suites that rely on `default_shell_command()` for a POSIX shell (AGENTS.md "Testing") stop being bash-by-construction, so they must pin a POSIX shell through a fixture helper; and the Workspace Trust comparison is made against the user's configured default, so confirm a built-in or plugin profile that names no program still never prompts. |
| ⬜ | TERM | **A pane whose shell has exited says so and offers Restart or Close** - verified: after `exit` the pane stays on screen with a cursor and no message, and `gpty list-panes` still counts it, so a crashed shell, a dropped `ssh` or a finished command looks like a hung pane. The exit code is already tracked (`TermStatus.exit_code`, `paneStatus`) but never shown. Fix: when the child has exited, draw an unobtrusive footer ("Process exited (code N) - Enter to restart, Ctrl+Shift+W to close") from the status the engine already reports; Restart re-spawns the pane's own spawn plan (program, args and the user's own per-pane env) through the same `validate_executable` path and keeps the pane's `attachment_id`; a Settings choice `On exit: keep / close` (default keep, so scrollback stays readable). Tests: exit 0 and non-zero, Restart re-runs the same plan, and the pane list and IPC state agree in both. |
| ⬜ | TERM | **Text attributes the emulator parses are drawn: strikethrough, dim, hidden, curly/dotted/dashed/double underline and underline colour** - verified: in a probe row of `ESC[1m` (bold), `[3m` (italic), `[4m` (underline), `[4:3m` (curly), `[9m` (strike) and `[2m` (dim), bold, italic and underline render and the other three do not. Cause (code): `CellInfo` in `term.rs` carries only `bold/italic/underline/inverse/wide`, so alacritty's strikeout, dim, hidden and underline-variant flags (and the SGR 58 colour) are dropped before the packer and the GUI never sees them; the exact flag set to carry is confirmed against `alacritty_terminal`'s `Flags` at pickup. These are not exotic: nvim draws diagnostics with undercurl, and many CLIs use dim for secondary text and strike for removed lines. Fix: replace the bool fields with a small attribute bitfield packed into the existing flat arrays (no per-cell `Dictionary`, per the AGENTS.md rendering note), thread it through the renderer-facing packer and `terminal_pane.gd`'s run batching (a run breaks on an attribute change, as it already does for underline), and draw strike as a rect, dim as the blended foreground, and undercurl as a pixel-aligned zig-zag. **Must land before v0.9.0's grid wire protocol freezes the packed layout.** Tests: a pixel diff against the current render for plain text and the three working attributes (the v0.5.3 batching technique), plus one assertion per new attribute. |
| ⬜ | TERM | **Box-drawing, block and braille characters are drawn by gPTY, not taken from the font** - verified: `┌─┐│└┘` renders at the default 14 px with visible gaps and a missing corner; block elements and braille are the same class. Font glyphs for these ranges are sized to the font's advance and ascent, not to the cell, which has a fractional pixel size, so neighbours neither join nor tile. `htop`, `btop`, `lazygit`, `tmux` borders and every TUI frame are built from them. Fix: draw U+2500–U+257F (box drawing), U+2580–U+259F (blocks) and U+2800–U+28FF (braille) procedurally as pixel-snapped rects in the cell's own rect, the approach Alacritty and kitty take, bypassing the font and leaving the text-run batching untouched for everything else. Powerline separators rendered correctly from the bundled DejaVu Sans Mono in the probe and stay font-drawn. Tests: a golden-pixel assertion that horizontally adjacent `─` and vertically adjacent `│` cells meet with no gap at several font sizes, including fractional cell sizes and the UI scale from the v0.8.0 theme item. |
| ⬜ | TERM | **Fonts: a chosen family with a fallback chain, so Nerd Font icons and combining marks render** - verified (symptoms), code (cause): Nerd Font private-use icons (`\uF015`, `\uF07B`, `\uF121`) rendered as small placeholder shapes instead of icons, and `e` + U+0301 lost its accent; CJK, colour emoji and Powerline separators rendered fine. Settings → Appearance offers a single font file (default `DejaVuSansMono.ttf`), the code sets no explicit fallback list, and `CellInfo.ch` is a single `char`, so a zero-width combining mark has nowhere to live (alacritty keeps them per cell; confirm at pickup). Fix: a font picker over system monospace families plus a file, an ordered fallback list, an optional bundled symbols-only fallback (a Nerd Fonts "Symbols Only" build - licence review at design time, as in the Rust media backend item), and combining-mark support (carry the marks through the packed grid and draw them on the base cell's origin). **Security coupling:** `_load_font` in `terminal_pane.gd` calls `load(path)` on a file-supplied path, and a Godot probe in the October 2026 security audit showed `load()` of a `.tres` with an embedded script runs its `_init` during the load - so the typed, extension-gated font loader that replaces it (`FontFile` from bytes; `.ttf`, `.otf`, `.ttc`, `.woff`, `.woff2`; never a resource loader) is owned by the first v0.7.1 item, and this item builds the picker, the fallback list and combining-mark support on top of that loader. |
| ⬜ | TERM | **Answer the terminal-state queries the emulator raises: OSC 4/10/11/12 colours and text-area size** - code: `TitleListener` in `term.rs` handles `Title` and `PtyWrite` and drops every other `TermEvent` into `_ => {}`. alacritty raises colour-request and text-area-size-request events for OSC 4/10/11/12 and `CSI 14/18 t` and expects the frontend to write the reply, so a program that asks for the terminal's background or palette never gets an answer. nvim, `bat`, `delta` and `lazygit` use the background query to pick a light or dark theme, and some wait out a timeout on every start. Not tested against a specific program yet - the first step is to run those four and record which ones stall. Fix: reply with fixed templates built from the pane's resolved palette (active scheme foreground, background and palette entries) and the cell and pixel size - the same class as the cursor-position and mode reports already forwarded, so nothing from the stream reaches the reply except the requested index - with a cap on pending replies per frame. Test: a real child (the `ShellFixtures` pattern) sends the query and reads back `ESC]11;rgb:…` from the pane. |
| ⬜ | TERM | **The bell is seen** - code: alacritty's bell event also falls into `_ => {}`, so `BEL` does nothing (the probe's frame diff was too noisy to add evidence). Fix: a brief accent on the pane's title bar, a badge on the pane's sidebar row and, when the pane is not in view, on its workspace row; `DisplayServer.window_request_attention()` when the window is unfocused; an optional system sound; a Settings choice `Bell: off / visual / visual + attention`, and a rate limit, because `cat` of a binary rings thousands of times. No full-screen flash (reduced-motion friendly). Display only, and nothing returns to the engine. The unseen-event marker introduced here is the one v0.9.1's activity item reuses, so build it as a shared sidebar badge rather than a bell-only one. |
| ⬜ | SEC | **Clipboard writes from programs (OSC 52), consent-gated and write-only** - code: alacritty's clipboard-store event is dropped, so `y` in nvim over SSH, tmux `set-clipboard` and any remote copy never reach the user's clipboard. Reads (the `?` query, clipboard-load) stay unimplemented permanently: a program reading your clipboard is an exfiltration path. Fix: honour store requests under a per-pane policy `ask (default) / allow / deny`; `ask` shows a non-modal toast with the byte count and Allow / Deny / Always-for-this-pane; the payload is base64-validated and decoded in Rust, capped (64 KiB to start), never logged, and only the focused pane may write without a prompt even under `allow`. The policy is user-owned state like `PaneEnvStore`: a layout, profile or plugin manifest cannot carry or pre-grant it. Needs the security review the parser's own comment requires for any new OSC, a line in `SECURITY.md`, and tests that a file cannot set the policy, an oversize or malformed payload is dropped, and a read request gets no reply. On Linux the primary-selection target maps to PRIMARY only once the v0.9.1 mouse-and-clipboard item exists; until then it is ignored. |
| ⬜ | TERM | **The shell's working directory is known: OSC 7 as display, "new pane here" as the default** - verified: after `cd /usr/share` in one pane, a new terminal started in `$HOME`, and no pane shows its directory anywhere (title, status bar, pane list). Code: alacritty ignores OSC 7, so this needs a bounded tap on the byte stream; the `gpty_state` OSC in `LineParser` is the precedent, and the tap must obey the same alt-screen, capture-replay and resize suppression (confirm the right place at pickup). Fix: parse `file://host/path`, accept only an empty or local host and an absolute path, percent-decode with a length cap, reject control bytes, and expose the result as a display field in `paneStatus` (like the exit code); show it in the pane title and status bar; make New Pane default to the active terminal's cwd (a setting turns it off). For shells that never emit OSC 7 (bash and zsh need a one-line hook, documented; fish emits natively), a Linux/macOS fallback from the shell's pid. Restoring each pane's last cwd on app restart rides on this using only user-owned `WorkspaceStore` state; layouts, profiles and plugin manifests stay unable to carry a cwd (the tile schema is closed), and a cwd is only ever used as a spawn directory, never as a program or argument. Tests: the parser accepts and rejects the forms above, the pane status carries the value, a new pane inherits it. |
| ⬜ | TERM | **Verify and fill the modern-TUI protocol set: kitty keyboard, focus reporting, synchronized output** - not tested; code: `keymap.rs` cites the kitty keyboard protocol in its header, but no mode negotiation or focus-reporting (DECSET 1004) or synchronized-output (DECSET 2026) handling turned up in the crates. Start by measuring: a probe child that sends the keyboard-mode query and DECRQM for 1004 and 2026 and prints the replies, run with nvim, helix and lazygit; record what `alacritty_terminal` already implements and what the pane drops. Then close the gaps in order of value: focus in/out events on pane activation (nvim `autoread`, tmux), synchronized output (no tearing under flood, which lines up with the flood cadence), and kitty keyboard disambiguation so `Ctrl+Shift` and `Ctrl+Enter` chords reach TUIs distinctly. Document the supported set in the docs and AGENTS.md. **S to measure, M to close.** |
| ⬜ | TERM | **A terminal fidelity regression suite** - the probes behind this release (the attribute row, the box/braille/CJK/emoji/combining row, `$SHELL`, exit, cwd, colour query, bell, OSC 52 denied by default) were one-off scratch scripts; commit them as tests. Rust `TermGrid` tests assert the per-cell attribute bits and combining marks; GUT integration tests drive a pane through `ShellFixtures` and assert rendered pixels (the `draw_bench.gd` pixel-diff technique) for the attribute and box-drawing cases, and read back the reply bytes for the query round trips. Add a supported-sequences table to the docs: what is interpreted, what is deliberately ignored, and why. |
| ⬜ | TERM | **Close the loop: re-run the probes on the v0.8.1 build** - same sandbox, synthetic-input and viewport-capture method, same fixtures; save the captures under `docs/static/images/` (`v0.8.1_<n>.png` for the finished state, `issue-v0.8.1-<slug>.png` for anything still open, listed under Screenshots on this page); every item above is closed or explicitly deferred with evidence, and the capture is the release's visual record. |
