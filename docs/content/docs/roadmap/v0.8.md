Five releases that make the interface the reason to use gPTY. v0.8.0 re-baselines the October 2026 audit, commits the capture harness, and lays down the shared theme, type scale, colour tokens, light theme and accessibility baseline. v0.8.1 is pane chrome, palette and discoverability. v0.8.2 is small windows, sidebar space and pane interaction. v0.8.3 is pane configuration, launch commands and profile identity. v0.8.4 is the Godot-native visual layer - shaders, pane transitions, reactive environments and a physical 3D vault graph - and the release capture. Every row in this chain is UI/UX work or the capture tooling that records it; build, security, MCP, distribution and promotion work lives in v0.9.

## v0.8.4 - Godot Visual Identity & Close-out

The differentiator release: the interface stops looking like a generic Godot app. Every effect is a setting, subtle or off by default, and display-only.

| ⬜ | GUI | **Dynamic Shaders** - GPU shader-based visual effects for terminal backgrounds and overlays (CRT scanlines, glassmorphism, noise). An orphan asset already exists - `godot/shaders/crt.gdshader` (`a477d82`, never referenced: no path or UID reference in any scene or script) - and it cannot be used as-is: its scanline term (`uv.y * SCREEN_PIXEL_SIZE.y * 500.0`) scales a 0–1 UV by a 1/resolution factor, so the whole node spans less than half a sine period (~0.46 rad at 1080p - a faint vertical ramp, not lines, and one that shifts with resolution), and `COLOR = texture(TEXTURE, uv)` drops the vertex/`modulate` color (a tinted overlay would render opaque white). **Pane spawn size** - row: *A fresh pane's child starts at 80×24 and only learns its real size 50 ms later* (closed). The `pane-spawn-size` capture state at 1280×760: the pane's program prints the PTY's own `stty size` before anything can have resized it, so the one line in the image - `41 rows, 129 cols` - is both the size its child was born at and the size it keeps. On the unfixed build the same tile's child started at 24×80 and was resized 50 ms later; a TUI that snapshots its size at startup kept the 80×24 layout until the next resize.

![A pane's child printing the size it was born at](/images/issue-v0.8.1-pane-spawn-size.png)

**Settings → Terminal's scrollbar** - row: *Every scrollable surface has a 0 px scrollbar* (closed). The `settings-terminal` capture state at 1920x1080, on the same 540x560 card the audit measured; its `settings-terminal-150` twin captures the same surface at a 150 % content scale, where the column is 12 device px. Box 1 is the tab's scrollbar column: 8 px of layout at the right inner edge of the tab - 8 px the `ScrollContainer` no longer gives its content - with the thumb as the lighter 6 px strip inside it, inset 1 px from the track and spanning 384 of the column's 441 px because the tab clears its card by only 62 px. On the unfixed build the bar measured (0, 441): no column, no grabber, nothing to drag.
