Five releases that make the interface the reason to use gPTY. v0.8.0 re-baselines the October 2026 audit, commits the capture harness, and lays down the shared theme, type scale, colour tokens, light theme and accessibility baseline. v0.8.1 is pane chrome, palette and discoverability. v0.8.2 is small windows and pane interaction. v0.8.3 is pane configuration, launch commands and profile identity. v0.8.4 is the Godot-native visual layer - shaders, pane transitions, reactive environments and a physical 3D vault graph - and the release capture. Every row in this chain is UI/UX work or the capture tooling that records it; build, security, MCP, distribution and promotion work lives in v0.9.

## v0.8.2 - Windows, Panes & Responsiveness

| Done | Area | Item |
|:---:|:---:|---|
| ⬜ | GUI | **Small windows adapt instead of clipping** - At 800×500 the Settings panel spills over the sidebar; at 560×340 it is clipped and overlaps pane titles, pane titles run under their own buttons, and the sidebar pane list is cut after one row. Fix: size panels relative to the viewport, ellipsize titles, let the sidebar scroll as a whole, and add 800×500 / 560×340 layout assertions. Screenshots (under Screenshots below): *Small window, 800×500* and *Small window, Settings*. |
| ⬜ | GUI | **Resizing a pane is smooth: the resize cursor always shows, no gray band while dragging, no hop on release** - three separate defects found together in the October 2026 usability pass, all reproduced against the v0.7.0 code. (1) *The resize cursor goes missing after a drag.* Verified: after dragging any divider, the cursor stays an arrow over some of the strips (on both axes) although the viewport's hover target is correct, and it comes back after a click in any pane. Cause: while a drag is active `Workspace._input` consumes every mouse event with `set_input_as_handled()`, including the button release, so the viewport never sees the release of the press the edge strip started. Its mouse-focus state stays stale and it stops updating the cursor shape until some other press-and-release pair reaches it. Fix: end the drag on the release but let the release continue to the GUI, consuming only the motion (verified in a scripted run through `Viewport.push_input`: with that change the cursor is correct over every strip after the drag). The release reaches only the strip that took the press, and `end_edge_drag` is already a no-op by then. (2) *A gray band shows while dragging.* Verified from captured frames: a terminal fills its whole rectangle with `default_bg`, `Color(0.12, 0.12, 0.12)`, while its cells use the engine's own default background (black, with no colour scheme selected), so the area the pane has grown into shows `(31,31,31)` beside `(0,0,0)` cells. The grid only reflows after `RESIZE_DEBOUNCE` (50 ms) with no further size change, which never happens mid-drag, and the old grid stays centred in the new rectangle until then. Fix: fill with the same colour the cells use (the engine's default background, or the selected scheme's), so the margin is invisible; and replace the quiet-period debounce with a throttle while a drag is active (about 10 reflows a second, one final reflow on release), so the text follows the divider the way other terminals do, without a window-size signal to the shell on every motion event. (3) *The divider hops on release.* The preview follows the pointer in pixels and the release rounds to one of 60 grid units, up to half a unit away, about 13 to 16 px across a 1920 px window. Fix: round the preview to units while dragging, so what is shown is what is committed. Also in this item: the strips are 6 px wide inside a 1 px border on each pane, so a divider has a 2 px dead band between two strips and a 14 px target in all. Replace the per-pane strips with one handle per divider line, wider than that and without the dead band, with a hover highlight on the divider, which stays visible even where the platform's cursor fails to change. Tests: a viewport-driven GUT test that presses, moves and releases and asserts the strip received the release and that no drag state is left behind; a frame-capture test that no pixel in the exposed margin differs from the cell background during a scripted drag (a magenta sentinel behind the grid also proves that no gap opens between panes); a preview-equals-commit assertion; and a manual check of the cursor on a windowed run, since the headless display driver has no cursor. |
| ⬜ | GUI | **Creating a pane gets slower as the window fills** - found 2026-10-30 while measuring the live-pane ceiling (a `new-pane` loop against the headless GUI, timing each call): the first pane is created in about 15 ms, the call took about 500 ms by 30 panes and about 1 s at 64 - the point where the grid's `MIN_TILE` floor refuses another tile - so the cost of a spawn grows with the live pane count instead of staying flat, and a user near the ceiling waits a second for each split. Candidate steps, not yet profiled: `_spawn_pane_into` -> `_add_body_to_grid_into` runs `_apply_layout`, `_sync_pane_titlebars` and `_list()` (a full sidebar rebuild) over every tile, and the settings broadcast re-applies to the whole window. Fix direction: profile one spawn at 64 panes (timers around each step) and make the create path cost per new pane rather than per live pane; a pass that must touch every tile belongs behind a coalesced frame. Tests: a wall-clock assertion is the wrong CI gate, so the check is the same harness re-run before and after (per-call latency, GUI RSS from `/proc/<pid>/status`, descendant count), with the before numbers in this row. |

## v0.8.4 - Godot Visual Identity & Close-out

The differentiator release: the interface stops looking like a generic Godot app. Every effect is a setting, subtle or off by default, and display-only.

| Done | Area | Item |
|:---:|:---:|---|
| ⬜ | GUI | **Dynamic Shaders** - GPU shader-based visual effects for terminal backgrounds and overlays (CRT scanlines, glassmorphism, noise). An orphan asset already exists - `godot/shaders/crt.gdshader` (`a477d82`, never referenced: no path or UID reference in any scene or script) - and it cannot be used as-is: its scanline term (`uv.y * SCREEN_PIXEL_SIZE.y * 500.0`) scales a 0–1 UV by a 1/resolution factor, so the whole node spans less than half a sine period (~0.46 rad at 1080p - a faint vertical ramp, not lines, and one that shifts with resolution), and `COLOR = texture(TEXTURE, uv)` drops the vertex/`modulate` color (a tinted overlay would render opaque white). Structural constraint: the terminal pane paints via batched `_draw()` commands, and a CanvasItem material runs per command with per-command `TEXTURE`/`UV` (font-atlas UVs for glyphs, 1×1 white with the tint in `COLOR` for rects), so a CRT effect belongs on a single-textured background quad (fixes: pixel-space scanline via `FRAGCOORD.y`; keep `* COLOR`) or on an overlay that reads `hint_screen_texture` and writes alpha to darken - never as a material on the grid Control. Deliver a closed table of built-in effects (a shader is code, so no path comes from a profile, a settings file or a plugin - the `PaneTypes.ALL` pattern), an `off`/`subtle`/`full` intensity setting with effects off by default, static effects cached rather than evaluated every frame, and `crt.gdshader` fixed or deleted in the same release. Glassmorphism uses the window-opacity row in this minor. |
| ⬜ | GUI | **Panes animate when they are created, destroyed or swapped** - the tile grid snaps every change in one frame: a new pane appears fully formed, a closed pane vanishes, and a swap teleports both bodies. Settings → Appearance → Motion: `off`, `subtle` (default), `full`, plus a per-transition toggle for create, destroy and swap; a change applies without restart. The layer must not run during a divider drag, on a hidden workspace, or while the flood throttle is active, and a layout change mid-flight kills the tween and jumps to the final rect. Tests: create/close/swap leave the grid rects exact; an interrupted tween frees its body exactly once; motion `off` draws the final state in one frame. |
