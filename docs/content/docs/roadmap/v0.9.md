Eight releases that measure the product and then close the gap between what gPTY claims and what it does. v0.9.0 is instrumentation: a diagnostics pane, opt-in hot-path timers, a gated performance budget, the idle render loop those numbers expose, and the first hot-path fixes those numbers justify. v0.9.1 and v0.9.2 are terminal fidelity - first how text is drawn, then what the emulator answers. v0.9.3 and v0.9.4 are the security, release-integrity, project-file and build-hygiene work left by the November 2026 review. v0.9.5 is everyday ergonomics. v0.9.6 is distribution and reach. v0.9.7 is enterprise readiness and dual-licensing: commercial license structuring, non-repudiable audit logging of agent PTY sessions, administrative security policy guardrails, headless token-based orchestration, and air-gapped installation packaging. The nightly channel rides in v0.9.3 rather than v0.9.6: it is a release-pipeline change, and it has to exist before the signature-asset and SBOM rows edit the same upload list.

## v0.9.0 - Instrumentation & Hot Paths

The release that makes cost a number instead of an adjective. The diagnostics pane is read-only and never carries program content; the timers are opt-in; the budget is the figure the UI/UX claim is measured against. The rows after the budget spend the number: a partial grid sync stops paying for the whole grid, the PTY path's guard stops walking bytes one at a time, and the note index stops walking a body it is only searching for a bracket.

The analysis behind those rows - which loops were measured, which are already vectorized upstream, and which candidates this release deliberately does not take - is a local working note at `TEMP/simd-opportunities.md` in the repository root. It is gitignored (the `TEMP*` entry in `.gitignore`) and never shipped; it exists so a row can be picked up without re-running the research.

The same question asked of the GDScript layer - which work is interpreter-bound, allocation-bound or crossing the FFI per item, and which work belongs in Rust - is a second local working note at `TEMP/gdscript-opportunities.md`. It is gitignored and never shipped. The repeatable half is committed: `scripts/gdscript-audit` ranks the candidates, `godot/tests/bench/gdscript_probe.gd` measures the idioms, and `docs/content/docs/agents/gdscript-performance.md` owns the method.

## v0.9.1 - Terminal Rendering Fidelity

Each item is marked verified (reproduced in the running app), code (read in the source, not run) or not tested. The theme: a daily driver is judged first on whether `htop`, `nvim`, `lazygit` and `ssh` look right inside the user's own shell. This is the drawing half; v0.9.2 is the answering half.
