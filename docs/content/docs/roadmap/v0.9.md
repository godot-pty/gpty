Seven releases that measure the product and then close the gap between what gPTY claims and what it does. v0.9.0 is instrumentation: a diagnostics pane, opt-in hot-path timers and a gated performance budget. v0.9.1 and v0.9.2 are terminal fidelity - first how text is drawn, then what the emulator answers. v0.9.3 and v0.9.4 are the security, release-integrity, project-file and build-hygiene work left by the November 2026 review. v0.9.5 is everyday ergonomics. v0.9.6 is distribution and reach.

## v0.9.0 - Instrumentation & Monitoring

The release that makes cost a number instead of an adjective. The diagnostics pane is read-only and never carries program content; the timers are opt-in; the budget is the figure the UI/UX claim is measured against.

| Done | Area | Item |
|:---:|:---:|---|
| ⬜ | GUI | **The app reports its own cost: frame time, CPU, memory and power** - the product claim is graphical fidelity, and the app measures none of what it costs: `godot/tests/bench/draw_bench.gd` times a forced repaint, but there is no in-app reading of idle frame time, resident memory, CPU or energy, so "smooth" and "cheap" are assertions. Fix: a built-in `diagnostics` pane (read-only, no PTY) that samples on a timer rather than per frame and shows (a) frame time split into idle and repaint, (b) resident memory and its peak, (c) process CPU, (d) power draw where the platform exposes it, and (e) per-pane rows - type, grid size, scrollback rows, PTY alive. The pane type joins `PaneTypes.ALL` and the `PaneType` enum in `gpty-core` spelled by `PaneType::as_str()` like every other type, so `new-pane`, the plugin-manifest validator's closed set and the did-you-mean list pick it up from the enumeration. Program content never appears: no captured text, no command lines, no environment values. |
| ⬜ | CORE | **Hot-path timers are opt-in and bounded** - nothing times the work the app is asked about: pane spawn, grid feed, the draw batch, IPC dispatch and the vault index. Fix: a small registry (Rust `Instant` for engine paths, `Time.get_ticks_usec()` for GDScript paths) that records count, total and max per named span, is off unless enabled in Settings → Performance or by an environment variable, keeps a ring of recent samples, and logs only span names and microseconds at `debug`. A disabled timer must compile to a branch, not a clock read, so enabling it is the only way frame pacing can change. |
| ⬜ | CORE | **Power draw is read where the OS exposes it, and says "unavailable" everywhere else** - a number invented from CPU time would be worse than no number. Fix: one trait with a platform source per OS - Linux `/sys/class/powercap/*/energy_uj` when readable and `/sys/class/power_supply/BAT*/power_now` as the fallback, Windows ETW's Energy Estimation provider, macOS `powermetrics` only when an already-privileged helper is present (otherwise unavailable) - with the source name and sample age shown beside the value. When no source is readable the pane prints "not available on this system", never an estimate. |
| ⬜ | TERM | **Input latency and throughput are measured and gated** - `godot/tests/bench/draw_bench.gd` measures draw cost, but nothing measures keystroke-to-pixel latency or sustained throughput, so "feels fast" is unevidenced. Fix: a harness that records (a) key event to grid change to the first frame that draws it, (b) MB/s through a flood with the flood throttle active (`cat` of a large file, `yes`), and (c) memory and SQLite size with 16 panes at full scrollback; record the numbers in this item and the CHANGELOG, add a loose CI regression gate (thresholds generous enough not to flake on shared runners, the lesson of the parallel-test item), and publish the figures in the docs. Make no claim about other terminals unless they are run under the same method. |
| ⬜ | BUILD | **A performance budget is stated and gated** - the diagnostic numbers have no consequence without a threshold. Fix: record a named build's idle frame time, full-repaint frame time at 90×30 and 200×60, resident memory at 1, 8 and 32 panes, startup to first frame, and the input-latency sample from the row above as a table in `docs/content/docs/agents/testing.md`; the bench harness fails when a run exceeds the budget by more than 10%. The budget is what the UI/UX claim is measured against, so a regression is a release blocker. |
| ⬜ | IPC | **The diagnostics pane is honest over the control surface** - `list-panes` reports type `diagnostics`; `pane-status` answers the latest samples as primitives; `inject`, `pane-run`, `pane-read` and `pane-wait` answer with a clear "not supported for diagnostics panes" error instead of silently succeeding; `new-pane --type diagnostics` works. Tests: each verb's response on a diagnostics pane, and a layout restore spawns the pane without a PTY and without error. |
| ⬜ | DOCS | **The v0.9.0 changelog records the instrumentation release** - release-time: write `docs/content/docs/changelog/v0.9.0.md`, link it from `CHANGELOG.md`, cover the diagnostics pane, the timer registry, the power-source rules and the gated budget, and capture the pane as `v0.9.0_<n>.png`. |

## v0.9.1 - Terminal Rendering Fidelity

Probes run against a sandboxed v0.6.0 build (commit `b8bf5f9`) with the same synthetic-input + viewport-capture method as the UX audit (AGENTS.md, "UI/UX assessment method"), plus a read of the emulator's event path in `crates/gpty-core/src/term.rs`. Each item is marked verified (reproduced in the running app), code (read in the source, not run) or not tested. The theme: a daily driver is judged first on whether `htop`, `nvim`, `lazygit` and `ssh` look right inside the user's own shell. This is the drawing half; v0.9.2 is the answering half.

| Done | Area | Item |
|:---:|:---:|---|
| ⬜ | TERM | **A pane cannot spawn when `$HOME` names no directory, and an empty workspace directory silently means `$HOME`** - found 2026-11-04 while running the GDScript suite: every pane failed with `Failed to spawn PTY for '/bin/bash': No such file or directory (os error 2)` although `/bin/bash` existed and ran, because the environment carried a `HOME` whose directory had been removed. Cause (code, portable-pty 0.9.0 `CommandBuilder::as_command`): the workspace directory is passed as `cwd`, and portable-pty substitutes `$HOME` whenever that is absent - `self.cwd.filter(is_dir).unwrap_or(home)` then `cmd.current_dir(dir)` - so an unusable `$HOME` becomes a `chdir` failure whose errno surfaces as "the program does not exist". Its `get_home_dir` falls back to `getpwuid` only when `$HOME` is unset, never when it is set and missing, and the gdext `cwd` sanitizer (which does drop a stale workspace directory) has no equivalent floor for the fallback. Two consequences: a launch whose `$HOME` is a stale mount, a deleted home or a container path that is not there fails every pane with a message naming the shell; and the documented meaning of an empty workspace directory ("Empty inherits gpty's" cwd, `gpty-gdext/src/lib.rs`) is wrong - the pane starts in `$HOME` (the prompt in the `agent-badges` capture reads `~` while the app's own cwd is the repository). Fix: resolve the start directory in one place before the spawn - the workspace directory when it is a directory, else gpty's own cwd when that is one, else `/` - pass it explicitly so portable-pty's `$HOME` substitution is never reached, and correct both comments. Tests: `HOME` set to a nonexistent path still spawns, and a pane with an empty workspace directory starts where the resolver says. |
| ⬜ | TERM | **The default shell is the user's shell, not `/bin/bash`** - verified: on a machine whose login shell is `/bin/fish` (`$SHELL` and `getent passwd` agree), every pane ran `bash` (`ps -p $$ -o comm=`), so the user's prompt, aliases and plugins were missing with no hint why. `SettingsManager.default_shell_command()` returns the literal `/bin/bash` on every non-Windows platform; on Windows it returns `%COMSPEC%`, i.e. `cmd.exe`, which is not what a Windows user opens a terminal for. Fix: resolve the fresh-install default from `$SHELL`, validated by the same rule `validate_executable` applies (absolute path, regular executable file), falling back to `/bin/bash` then `/bin/sh`; on Windows prefer `pwsh.exe`, then `powershell.exe`, then `%COMSPEC%`, found by absolute path. Settings → Terminal lists the detected shells (including installed WSL distributions) as choices beside the free-text path, and shows what the default resolved to. A saved `shell_command` is never overwritten. Two knock-on points to handle in the same item: the GUT suites that rely on `default_shell_command()` for a POSIX shell (AGENTS.md "Testing") stop being bash-by-construction, so they must pin a POSIX shell through a fixture helper; and the Workspace Trust comparison is made against the user's configured default, so confirm a built-in or plugin profile that names no program still never prompts. |
| ⬜ | TERM | **A pane whose shell has exited says so and offers Restart or Close** - verified: after `exit` the pane stays on screen with a cursor and no message, and `gpty list-panes` still counts it, so a crashed shell, a dropped `ssh` or a finished command looks like a hung pane. The exit code is already tracked (`TermStatus.exit_code`, `paneStatus`) but never shown. Fix: when the child has exited, draw an unobtrusive footer ("Process exited (code N) - Enter to restart, Ctrl+Shift+W to close") from the status the engine already reports; Restart re-spawns the pane's own spawn plan (program, args and the user's own per-pane env) through the same `validate_executable` path and keeps the pane's `attachment_id`; a Settings choice `On exit: keep / close` (default keep, so scrollback stays readable). Tests: exit 0 and non-zero, Restart re-runs the same plan, and the pane list and IPC state agree in both. |
| ⬜ | TERM | **Text attributes the emulator parses are drawn: strikethrough, dim, hidden, curly/dotted/dashed/double underline and underline colour** - verified: in a probe row of `ESC[1m` (bold), `[3m` (italic), `[4m` (underline), `[4:3m` (curly), `[9m` (strike) and `[2m` (dim), bold, italic and underline render and the other three do not. Cause (code): `CellInfo` in `term.rs` carries only `bold/italic/underline/inverse/wide`, so alacritty's strikeout, dim, hidden and underline-variant flags (and the SGR 58 colour) are dropped before the packer and the GUI never sees them; the exact flag set to carry is confirmed against `alacritty_terminal`'s `Flags` at pickup. These are not exotic: nvim draws diagnostics with undercurl, and many CLIs use dim for secondary text and strike for removed lines. Fix: replace the bool fields with a small attribute bitfield packed into the existing flat arrays (no per-cell `Dictionary`, per the AGENTS.md rendering note), thread it through the renderer-facing packer and `terminal_pane.gd`'s run batching (a run breaks on an attribute change, as it already does for underline), and draw strike as a rect, dim as the blended foreground, and undercurl as a pixel-aligned zig-zag. **Must land before v0.10.0's grid wire protocol freezes the packed layout.** Tests: a pixel diff against the current render for plain text and the three working attributes (the v0.5.3 batching technique), plus one assertion per new attribute. |
| ⬜ | TERM | **Box-drawing, block and braille characters are drawn by gPTY, not taken from the font** - verified: `┌─┐│└┘` renders at the default 14 px with visible gaps and a missing corner; block elements and braille are the same class. Font glyphs for these ranges are sized to the font's advance and ascent, not to the cell, which has a fractional pixel size, so neighbours neither join nor tile. `htop`, `btop`, `lazygit`, `tmux` borders and every TUI frame are built from them. Fix: draw U+2500–U+257F (box drawing), U+2580–U+259F (blocks) and U+2800–U+28FF (braille) procedurally as pixel-snapped rects in the cell's own rect, the approach Alacritty and kitty take, bypassing the font and leaving the text-run batching untouched for everything else. Powerline separators rendered correctly from the bundled DejaVu Sans Mono in the probe and stay font-drawn. Tests: a golden-pixel assertion that horizontally adjacent `─` and vertically adjacent `│` cells meet with no gap at several font sizes, including fractional cell sizes and the UI scale from the v0.8.0 theme item. |
| ⬜ | TERM | **Fonts: a chosen family with a fallback chain, so Nerd Font icons and combining marks render** - verified (symptoms), code (cause): Nerd Font private-use icons (`\uF015`, `\uF07B`, `\uF121`) rendered as small placeholder shapes instead of icons, and `e` + U+0301 lost its accent; CJK, colour emoji and Powerline separators rendered fine. Settings → Appearance offers a single font file (default `DejaVuSansMono.ttf`), the code sets no explicit fallback list, and `CellInfo.ch` is a single `char`, so a zero-width combining mark has nowhere to live (alacritty keeps them per cell; confirm at pickup). Fix: a font picker over system monospace families plus a file, an ordered fallback list, an optional bundled symbols-only fallback (a Nerd Fonts "Symbols Only" build - licence review at design time, as in the Rust media backend item), and combining-mark support (carry the marks through the packed grid and draw them on the base cell's origin). **Security coupling:** the typed, extension-gated font loader this item builds on shipped in v0.7.1 as `TerminalFonts` (`FontFile` from bytes, an absolute regular file, extension + magic + face checks; `.ttf`, `.otf`, `.ttc`, `.woff`, `.woff2`, never a resource loader), so the picker, the ordered fallback chain (the loader takes one path today) and combining-mark support are built on top of it. |
| ⬜ | TERM | **A per-pane font is saved but overwritten on every restore, so a chosen font only survives in-session** - found while closing the v0.7.1 resource-loading item: `Workspace._restore_into` applies a tile's settings and then `SettingsManager.apply_to_terminal`, so the saved `font_path` loses to `cfg_font_path`; a per-pane colour scheme no longer round-trips at all (the v0.7.1 fix made it runtime-only and stopped saving it). Decide with the font picker and fallback chain above: either the tile wins for that pane (the value is already validated by the closed settings table and `TerminalFonts`) or the global wins and the pane panel stops offering a per-pane choice. Add the save → restore test for a chosen font, which the fallback chain will need anyway. |
| ⬜ | TERM | **A terminal pane spawned with `-c` can show an empty body after its command finishes** - found 2026-11-06 while recording `demo-panes`: two panes were spawned in one run - `gpty new-pane -t terminal -c 'ls' --title files` (output rendered) and `gpty new-pane -t terminal -c 'git log --oneline --graph' --title log`, whose body stayed blank for the four seconds until the next cue, while the pane existed, was focused and drew its title, so the spawn answered. The same `git log` injected into an interactive shell after spawn rendered at once, which is what the shipped clip now does. Cause not measured: either the child's output raced the pane's grid attach (spawn, write and exit inside one frame) or the pane clears its grid when the child exits in the frame the first update is applied. Fix: capture `-c 'echo one; sleep 0.2; echo two'` and `-c true` at spawn to separate the two, then keep the grid's scrollback instead of resetting it on child exit; a regression test drives `-c` through `newPane` and asserts the text is in `pane-read`. |
| ⬜ | DOCS | **The v0.9.1 changelog records the rendering work** - release-time: write `docs/content/docs/changelog/v0.9.1.md`, link it from `CHANGELOG.md`, cover the default shell, the exit footer and restart, the drawn attributes, box/block/braille drawing, the font fallback chain and the per-pane font fix, and capture them as `v0.9.1_<n>.png`. |

## v0.9.2 - Terminal Protocol Fidelity

The second fidelity release: what the emulator must reply to, and the regression suite that keeps both halves honest.

| Done | Area | Item |
|:---:|:---:|---|
| ⬜ | TERM | **Answer the terminal-state queries the emulator raises: OSC 4/10/11/12 colours and text-area size** - code: `TitleListener` in `term.rs` handles `Title` and `PtyWrite` and drops every other `TermEvent` into `_ => {}`. alacritty raises colour-request and text-area-size-request events for OSC 4/10/11/12 and `CSI 14/18 t` and expects the frontend to write the reply, so a program that asks for the terminal's background or palette never gets an answer. nvim, `bat`, `delta` and `lazygit` use the background query to pick a light or dark theme, and some wait out a timeout on every start. Not tested against a specific program yet - the first step is to run those four and record which ones stall. Fix: reply with fixed templates built from the pane's resolved palette (active scheme foreground, background and palette entries) and the cell and pixel size - the same class as the cursor-position and mode reports already forwarded, so nothing from the stream reaches the reply except the requested index - with a cap on pending replies per frame. Test: a real child (the `ShellFixtures` pattern) sends the query and reads back `ESC]11;rgb:…` from the pane. |
| ⬜ | TERM | **The bell is seen** - code: alacritty's bell event also falls into `_ => {}`, so `BEL` does nothing (the probe's frame diff was too noisy to add evidence). Fix: a brief accent on the pane's title bar, a badge on the pane's sidebar row and, when the pane is not in view, on its workspace row; `DisplayServer.window_request_attention()` when the window is unfocused; an optional system sound; a Settings choice `Bell: off / visual / visual + attention`, and a rate limit, because `cat` of a binary rings thousands of times. No full-screen flash (reduced-motion friendly). Display only, and nothing returns to the engine. The unseen-event marker introduced here is the one v0.9.5's activity item reuses, so build it as a shared sidebar badge rather than a bell-only one. |
| ⬜ | SEC | **Clipboard writes from programs (OSC 52), consent-gated and write-only** - code: alacritty's clipboard-store event is dropped, so `y` in nvim over SSH, tmux `set-clipboard` and any remote copy never reach the user's clipboard. Reads (the `?` query, clipboard-load) stay unimplemented permanently: a program reading your clipboard is an exfiltration path. Fix: honour store requests under a per-pane policy `ask (default) / allow / deny`; `ask` shows a non-modal toast with the byte count and Allow / Deny / Always-for-this-pane; the payload is base64-validated and decoded in Rust, capped (64 KiB to start), never logged, and only the focused pane may write without a prompt even under `allow`. The policy is user-owned state like `PaneEnvStore`: a layout, profile or plugin manifest cannot carry or pre-grant it. Needs the security review the parser's own comment requires for any new OSC, a line in `SECURITY.md`, and tests that a file cannot set the policy, an oversize or malformed payload is dropped, and a read request gets no reply. On Linux the primary-selection target maps to PRIMARY only once the v0.9.5 mouse-and-clipboard item exists; until then it is ignored. |
| ⬜ | TERM | **The shell's working directory is known: OSC 7 as display, "new pane here" as the default** - verified: after `cd /usr/share` in one pane, a new terminal started in `$HOME`, and no pane shows its directory anywhere (title, status bar, pane list). Code: alacritty ignores OSC 7, so this needs a bounded tap on the byte stream; the `gpty_state` OSC in `LineParser` is the precedent, and the tap must obey the same alt-screen, capture-replay and resize suppression (confirm the right place at pickup). Fix: parse `file://host/path`, accept only an empty or local host and an absolute path, percent-decode with a length cap, reject control bytes, and expose the result as a display field in `paneStatus` (like the exit code); show it in the pane title and status bar; make New Pane default to the active terminal's cwd (a setting turns it off). For shells that never emit OSC 7 (bash and zsh need a one-line hook, documented; fish emits natively), a Linux/macOS fallback from the shell's pid. Restoring each pane's last cwd on app restart rides on this using only user-owned `WorkspaceStore` state; layouts, profiles and plugin manifests stay unable to carry a cwd (the tile schema is closed), and a cwd is only ever used as a spawn directory, never as a program or argument. Tests: the parser accepts and rejects the forms above, the pane status carries the value, a new pane inherits it. |
| ⬜ | TERM | **Verify and fill the modern-TUI protocol set: kitty keyboard, focus reporting, synchronized output** - not tested; code: `keymap.rs` cites the kitty keyboard protocol in its header, but no mode negotiation or focus-reporting (DECSET 1004) or synchronized-output (DECSET 2026) handling turned up in the crates. Start by measuring: a probe child that sends the keyboard-mode query and DECRQM for 1004 and 2026 and prints the replies, run with nvim, helix and lazygit; record what `alacritty_terminal` already implements and what the pane drops. Then close the gaps in order of value: focus in/out events on pane activation (nvim `autoread`, tmux), synchronized output (no tearing under flood, which lines up with the flood cadence), and kitty keyboard disambiguation so `Ctrl+Shift` and `Ctrl+Enter` chords reach TUIs distinctly. Document the supported set in the docs and AGENTS.md. **S to measure, M to close.** |
| ⬜ | TERM | **A terminal fidelity regression suite** - the probes behind this release (the attribute row, the box/braille/CJK/emoji/combining row, `$SHELL`, exit, cwd, colour query, bell, OSC 52 denied by default) were one-off scratch scripts; commit them as tests. Rust `TermGrid` tests assert the per-cell attribute bits and combining marks; GUT integration tests drive a pane through `ShellFixtures` and assert rendered pixels (the `draw_bench.gd` pixel-diff technique) for the attribute and box-drawing cases, and read back the reply bytes for the query round trips. Add a supported-sequences table to the docs: what is interpreted, what is deliberately ignored, and why. Reference for that table, so the expected behavior is not invented from our own implementation: [xterm Control Sequences](https://invisible-island.net/xterm/ctlseqs/ctlseqs.html) for what each sequence means, iTerm2's `esctest` and `vttest` as conformance suites whose cases can be borrowed, and UAX #11 (East Asian Width), UAX #29 (grapheme clusters) and UTS #51 (emoji) for cell advance and cursor movement. |
| ⬜ | TERM | **Close the loop: re-run the probes on the v0.9.2 build** - same sandbox, synthetic-input and viewport-capture method, same fixtures; save the captures under `docs/static/images/` (`v0.9.2_<n>.png` for the finished state, `issue-v0.9.2-<slug>.png` for anything still open, listed under a Screenshots section at the bottom of this page); every item above is closed or explicitly deferred with evidence, and the capture is the release's visual record. |
| ⬜ | DOCS | **The v0.9.2 changelog records the protocol work** - release-time: write `docs/content/docs/changelog/v0.9.2.md`, link it from `CHANGELOG.md`, cover the colour and text-area replies, the bell, OSC 52, OSC 7, the kitty/focus/synchronized-output checks and the regression suite, and use the `v0.9.2_<n>.png` captures. |

## v0.9.3 - Security & Release Integrity

The November 2026 health review's repository and release controls. Main protection, org-wide 2FA and the OpenSSF Best Practices passing badge landed on 2026-11-02 - the first is recorded in v0.7.2, the other two below. This release is repository settings, then release integrity; the project files and build hygiene are v0.9.4. Deliberately out of scope: SLSA L3/reproducible builds, a CLA, coverage gates, OSS-Fuzz and ISO 27001 - L2 with visible signatures and an SBOM is the proportionate target; the deferred ideas stay in Future.
