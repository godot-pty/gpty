Follow-ups to the v0.6.0 knowledge base that were parked as unscheduled work: two heading-anchor defects, derived related-note suggestions, templates and daily notes, and shared graph nodes in the concept editor.

v0.12.1 adds the Markdown authoring surface: the formatting toolbar the note editor never had, the heading outline and find-in-note that go with it, and the follow-ups the research spike on Markdown editors found once those were specified.

## v0.12.0 - Knowledge Base Follow-ups

| Done | Area | Item |
|:---:|:---:|---|
| ⬜ | WIKI-37 | **A heading whose text also appears in the body can land the preview on the body line** - `MarkdownView.scroll_to_heading` searches the *rendered text* for the heading's line (that is what makes source lines and rendered lines agree), so a paragraph that says exactly the same thing and appears first wins the search. Found while closing the fragment item (2026-10-18); the renderer emits no anchors, so text matching was the chosen approach. Display-only - a wrong scroll inside the right note, never a wrong note. Fix direction only if it is noticed in use: have `GptyMarkdown.render` track each heading's plain-text offset while emitting events and map that offset with `get_character_line`, or emit an invisible marker the view can find. |
| ⬜ | WIKI-38 | **Setext headings have no anchor** - `MarkdownAnchors` recognizes ATX (`#`) headings only, so `[[note#Title]]` does not land on a `Title` over `===` heading, and a source line under one derives no anchor (it lands at the nearest ATX heading above, or the top). The preview renders setext headings (pulldown-cmark does), so the gap is navigation, not display. Found while closing the fragment item (2026-10-18); rare in Obsidian-shaped notes, which is why it was scoped out. Fix direction: add the two-line `===`/`---` form to the scanner - carefully, because a leading `---` is frontmatter and a thematic break is not a heading. |
| ⬜ | WIKI-39 | **Suggested related notes from the FTS index** - score a note's own top terms against the rest of the vault (`notes_fts` already holds them, porter-stemmed) and surface the neighbours as *suggestions*: fully derived, no store, no authoring, no trust question, display-only like everything else in the graph. This is the middle layer between measured mention counts and declared weights (v0.6.0), and it answers "what else is about this" without an LLM; queue it once the link layer has settled. |
| ⬜ | WIKI-40 | **Templates** - a designated folder whose contents are inserted into the open note with a **closed token table** (`{{date}}`, `{{time}}`, `{{title}}`, `{{vault}}`) expanded in Rust and inserted as an *edit*, so the user still saves and templates open no second write path into the vault. Parked off-release by the owner's call (2026-10) because nothing depends on it; scheduled here by the roadmap restructure, and it still adds no trust surface. The scripting half of this on the Obsidian side is its Templater plugin - the ecosystem this project stays out of. **Daily notes are a cron-job on a template** (open or create `<folder>/<pattern>.md` for today, then apply one) and can ride along when this is built, reusing the create-note verb; they are not worth an item of their own. |
| ⬜ | CONCEPT-14 | **Shared graph nodes (free DAG)** - the visual editor's rules are chains because a compiled entry's identity is the trigger's name: one trigger = one rule, and a shared condition or action would compile two entries under one name. Fan-in/fan-out needs OR'd triggers (`triggers: [regex…]`) and a rule id independent of the trigger name in the vocabulary. Deferred from v0.5.4 - revisit with demand evidence, not before. |
| ⬜ | DOCS-43 | **Capability catalogue: AGENT** - record the agent surface the way TERM, IPC, GUI and WIKI are recorded: the event socket's vocabulary and its capability scoping (`crates/gpty-gdext/src/omp_events.rs`), the four badge silhouettes and what each is derived from (`godot/scenes/ui/agent_badge.gd`), capture routing (`crates/gpty-core/src/concept.rs`, `crates/gpty-gdext/src/capture_api.rs`), the private Inspector bridge (`crates/gpty-gdext/src/ai.rs`, `godot/scenes/panes/inspector_pane.gd`) and the Reasoning projection. Schema, statuses and gate are in `docs/content/docs/agents/testing.md`; acceptance is `./scripts/check-capabilities` green with the new area. |
| ⬜ | DOCS-44 | **Capability catalogue: CONCEPT** - the concept engine is the one place gPTY acts on program output, and no record states its contract: trigger matching and capture routing as pure functions (`crates/gpty-core/src/concept.rs`), the capture state machine and its modes (`crates/gpty-core/src/engine.rs`), the default concept set (`godot/concepts.default.json`), the routing that decides which pane receives a capture (`godot/scenes/terminal/concept_router.gd`) and the `gpty_state` OSC as the declaration path (`crates/gpty-core/src/parser.rs`). |
| ⬜ | DOCS-45 | **Two shipped GUI capabilities are still recorded as planned** - found 2026-11-21 while adding the effects record: `docs/data/capabilities/GUI.json` says `gui.chrome.opacity` is planned ("neither setting exists") and `gui.scheme.import` is planned ("only three schemes ship and no importer exists"), while both owning rows closed in v0.8.6 (**Window fit: opacity and inner padding**, **Colour schemes: import, and light mode that follows the system**). `scripts/check-capabilities` validates shape, ids and evidence but never compares a record's `status` with its `row`'s ✅/⬜ mark, so a closed row leaves a stale claim that the docs page and every catalogue reader repeat. Fix: correct both records (status done, mechanism and evidence current), and teach `check-capabilities` to fail a `planned` record whose roadmap row is ✅ (or a `done` record whose row is ⬜) by parsing the roadmap pages it already joins against; then re-check the other three areas for the same drift. |
| ⬜ | DOCS-46 | **Capability catalogue: MEDIA** - the media backend's properties are its allowlists and its bounds, not its features: the path gate and component allowlists (`crates/gpty-media/src/lib.rs`), stream selection and demuxer aliases (`probe.rs`), the decode thread's bounded queues and seek epochs (`session.rs`), the packed RGBA/PCM wire (`crates/gpty-gdext/src/media_api.rs`) and what the pane refuses (`godot/scenes/panes/media_files.gd`). Several of these are security properties, so the record is the place a regression would show up as a missing capability rather than a silent widening. |
| ⬜ | DOCS-47 | **Capability catalogue: CLI** - the command surface is a published contract (27 MCP tools, a skill printed by `gpty --skill`) with no inventory behind it: argv-only spawn and the stale-binary check (`crates/gpty-cli/src/main.rs`), the argument translation and its refusals (`commands/wire.rs`), the tool-name gate (`commands/schema.rs`), daemon start/stop/status, plugin verbs and the layout verbs. |
| ⬜ | DOCS-48 | **Capability catalogue: PLUGIN** - record what a plugin may and may not do: manifest validation and its caps (`godot/scenes/terminal/plugin_review_text.gd` and the shipped validator), the clone-review-consent handshake and the trust store (`godot/scenes/autoloads/trusted_store.gd`), the registry index and its policies (`godot/assets/registry.json`), and the per-plugin config/state/log directories. The record is the audit surface for the next `plugins.md` change. |
| ⬜ | DOCS-49 | **Capability catalogue: SEC** - the trust boundaries are currently described in prose in `SECURITY.md` and `docs/content/docs/agents/security.md`, so a control can be weakened without a record noticing: workspace trust, the plugin review, the vault root registry, the OSC 52 write policy, owner-only store files (`crates/gpty-core/src/owner_only.rs`) and the log-hygiene rule. Each becomes a record whose `mechanism` names the enforcement point and whose `evidence` is the code, so deleting the enforcement breaks the gate rather than the documentation's accuracy. |
| ⬜ | DOCS-50 | **Capability catalogue: CORE** - the engine's own contract: PTY spawn and validation (`crates/gpty-core/src/pty.rs`), the vte-to-grid feed and damage tracking (`term.rs`), capture modes and the capture state machine (`engine.rs`), scrollback store plumbing and damaged-file recovery (`store.rs`, `history.rs`), and the keymap. This is the area where a `partial` record is a fidelity bug with a name. |

## v0.12.1 - Markdown Authoring

The note editor's authoring surface. The rows are ordered the way the queue is: the correctness item first,
the toolbar next as the release's headline, then the surface's navigation, then the authoring and renderer
depth that follow from it, then polish.

The implementation spec for these rows - the exact APIs, literals, chords and test cases the research
settled - is a local working note at `TEMP/markdown-authoring-plan.md` in the repository root. It is
gitignored (the `TEMP*` entry in `.gitignore`) and never shipped; it exists so a row can be picked up
without re-running the research.

| Done | Area | Item |
|:---:|:---:|---|
| ⬜ | WIKI-41 | **Markdown lint for the open note** - three defects are silent today: an unclosed fence swallows the rest of the note in the preview (the renderer parses what it is given and nothing compares the fence count), a `[[mention]]` that resolves to nothing is visible only in the link panel, and two headings with the same text make `[[note#heading]]` ambiguous (`MarkdownAnchors.find` returns the first). Fix: a pure `MarkdownLint` scanner beside `godot/scenes/ui/markdown_anchors.gd`, reusing `MarkdownAnchors` and the index's link parser; a status row under the note toolbar ("1 unclosed fence, 2 unresolved links") that opens a popup listing each with its line; click-to-jump through `_scroll_open_note`, which already scrolls the source by line and the preview by `MarkdownView.scroll_to_source_line`; and no auto-fix - a lint item names a line and never edits the buffer. |
| ⬜ | WIKI-42 | **Markdown formatting toolbar** - the note editor is a bare `CodeEdit` (`godot/scenes/panes/wiki_pane.gd:311`) under a view-mode row, so bold, lists, tables and links are typed by hand even though the renderer already supports them (GFM tables, strikethrough and task lists; `crates/gpty-gdext/src/markdown.rs:164-168`). Fix: a `FormatBar` under the action row - an `HFlowContainer` so a narrow tile wraps instead of clipping - built from `Icons.icon_button` buttons for bold, italic, strikethrough, inline code, link, wikilink, heading level (menu), bullet/numbered/task list, quote, code fence and table, wired into the existing note-toolbar `KeyboardFocus` ring; edit computation as a pure module (`godot/scenes/ui/markdown_format.gd`, the `MarkdownAnchors` shape) answering line/column range edits that the pane applies inside one `begin_complex_operation`, so an action is one undo step with the selection and scroll restored; chords declared pane-local in `ShortcutManager._ready` (`declare`, not `register` - the `term:*` precedent - so a terminal's `Ctrl+B` is untouched) and read by the editor's own input handler; `AppDialog`-based Link, Wikilink and Table dialogs, the Link one stating that only http/https/mailto render. Alignment is GFM's only: the table dialog writes `:---`/`:---:`/`---:` markers, and because Godot's BBCode table has no per-column horizontal alignment the renderer aligns each cell with `[center]`/`[right]` for those markers to show - probe it in a capture before relying on it, and if cells do not align, keep the source markers and say in the tooltip that the preview renders tables left-aligned. Chords: `Ctrl+B`/`Ctrl+I`/`Ctrl+K`, `Ctrl+Shift+X` (strike), `Ctrl+E` (inline code), `Ctrl+Shift+E` (fence), `Ctrl+Shift+7`/`8`/`9` (numbered/bullet/quote), `Ctrl+Alt+K` (wikilink). |
| ⬜ | WIKI-43 | **Outline navigator** - `MarkdownAnchors.headings` already scans ATX headings for link fragments, but nothing shows them, so a long note is navigated by scrolling; `_atx_heading` computes the level and then drops it, so the scanner cannot even express indentation. Fix: append `level` to each `headings()` entry; a toggleable `OutlinePanel` - an `ItemList` (one tab stop, arrows, Enter jumps) in a `ScrollContainer`, about 140 px - as the first column of the note view, refreshed on a 0.3 s debounce off the buffer and capped at 200 rows with a counted footer; a jump reuses `_scroll_open_note`, so it scrolls the source in edit/split and the rendered heading in preview; the toggle persists per tile as `outline`, following the `graph` rule (`WIKI_SETTINGS` in `godot/scenes/panes/pane_types.gd:591`: `ipc: false`, replayed once at attach, never moved by a settings re-apply). |
| ⬜ | WIKI-44 | **Find in the open note** - the pane's search box queries the vault index only (`_run_search`), so there is no way to find text in the note on screen. Fix: `Ctrl+F` opens a find strip above the buffer; `TextEdit.set_search_text` highlights every match and `TextEdit.search(text, flags, from_line, from_column)` (4.7; `SEARCH_MATCH_CASE`, `SEARCH_BACKWARDS`; answers column/line as a `Vector2i`) steps next and previous with wrap-around and a "No matches" status; the match length is the query length, exact for the single-line plain-text queries the strip accepts; Escape in the field closes the strip, which means the pane's `_input` must decline Escape there (today it is Back for every other focus owner in the note view); the strip clears when the note closes. Replace is deliberately out: it needs its own undo story. |
| ⬜ | WIKI-45 | **Images in notes render as nothing** - `Tag::Image` is reduced to `[i]Image: alt[/i]` (`crates/gpty-gdext/src/markdown.rs`), so a note written elsewhere (Obsidian embeds images routinely) shows no image at all, and nothing can insert one. Fix: resolve a relative image path against the vault root under the walk's containment rule (`gpty_core::vault`: canonicalize, refuse anything outside the root), a closed extension set (`.png`, `.jpg`, `.jpeg`, `.gif`, `.webp`) and a byte and pixel cap before decode, into a texture the view holds and `[img]`s; a toolbar action opens a picker inside the vault and inserts `![alt](relative/path)`. Remote URLs stay alt text - the renderer has no network path and this release does not add one. |
| ⬜ | WIKI-46 | **Table editor** - a table can be inserted by the toolbar and then only hand-edited: adding a row means typing a pipe line in the right shape, and a cell containing a `\|` breaks the row. Fix: caret-aware commands on the Table menu - insert row above/below, delete row, insert column left/right, delete column, and align the column under the caret - as pure `MarkdownFormat` edits (one undo step, delimiter row preserved, widths untouched), disabled when no table is under the caret (`table_at`). A grid or cell editor view is deliberately not attempted: the source is the document. |
| ⬜ | WIKI-47 | **Wikilink autocomplete** - `[[` is the vault's link syntax and the pane renders and follows it, but writing one means recalling a note's exact stem; a misspelling silently becomes an unresolved link, and create-from-link then offers to fork the note. Fix: typing `[[` opens a completion list fed by the existing FTS index (`vault_search`, capped at 10, debounced 150 ms), Up/Down/Enter/Tab pick, Escape cancels, and the insert writes the stem (alias form `[[stem\|alias]]` when text is selected); the popup is anchored at the caret, works with mouse and keyboard, and leaves the pane's existing leave rules unchanged. |
| ⬜ | WIKI-48 | **Preview depth: fenced-code highlighting and footnotes** - a fenced block renders as one `[code]` run whose info string is literal first text, and `Options::ENABLE_FOOTNOTES` is off (`crates/gpty-gdext/src/markdown.rs:164-168`) although the `FootnoteDefinition`/`FootnoteReference` arms already exist. Fix: (a) a closed language table (`rs`, `py`, `gd`, `js`/`ts`, `sh`/`bash`, `json`, `toml`, `yaml`, `c`, `cpp`, `md`) mapping keywords, strings and comments to `[color]` spans - a token scan in the renderer, no new dependency, and anything unlisted stays plain; (b) enable footnotes and link `[^1]` to its definition. Display only: the source is untouched. |
| ⬜ | WIKI-49 | **Editor conveniences: list continuation, task toggling, and a word count** - Enter at the end of `- item` starts a plain line, so the marker is re-typed; a checklist is ticked by editing `[ ]` by hand; and nothing reports the document's length. Fix: Enter continues the current list or quote prefix and a second Enter on an empty item clears it (a pure prefix computation shared with the toolbar's list commands); a task toggle flips `- [ ]`/`- [x]` on every touched line from the toolbar and a chord; the note bar shows `words · characters` from a 0.5 s debounced count and hides in preview mode. No new store and no new write path. |
