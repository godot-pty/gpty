## v0.13.0 - Agent Backends

| Done | Area | Item |
|:---:|:---:|---|
| ⬜ | AGENT | **A turn that fails mid-protocol never says what the omp child printed** - found 2026-10-31 while closing v0.7.1's logging item, which moved backend stderr to `debug` because program output is not log material. `OmpProcess::describe_failure` appends the bounded `StderrTail` to a *start-up* failure, but a turn that fails after the handshake emits `AiEvent::Error` with the protocol error alone (`omp.rs`, `run_omp_session`'s `if let Err(error) = result`), so the provider error the child wrote to stderr is visible neither in the pane nor in the console. The respawn path makes it worse: a new `OmpProcess` replaces the old one, so the dying child's tail - the one that explains the crash - is dropped with it. Fix: freeze the tail per turn (a slice `run_omp_session` takes before a respawn discards the process) and append it to the turn's error message when non-empty, in the format `describe_failure` already uses; test with a fake omp that greets `ready`, prints an escape-wrapped line to stderr on `prompt` and exits, asserting the pane's error carries the stripped text. |
| ⬜ | AGENT | **Inspector / Reasoning follow-ups** - host-tools bridge and OpenAI-compatible HTTP still planned. Provider-specific CLI adapters follow the v0.5.2 generic `CliBackend` lane: documented hooks/extensions only, never token reuse or TUI scraping. |
