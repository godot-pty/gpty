[Release on GitHub](https://github.com/godot-pty/gpty/compare/v0.8.2...v0.8.3)

v0.8.3 is about where a pane lives and how fast it gets there. Small windows adapt instead of clipping, the sidebar's Workspaces, Profiles and Panes sections fold, and a pane can be configured from outside the app - its own settings, its wiki view state, a move to another workspace - while the resize handles, the toast queue and the scroll chevrons stop being approximations.

Under the surface the switch, spawn and paint costs came down and the OMP event channel stopped running seconds behind the session: a one-row change repaints one row, a streaming pane follows the frame cadence, a spawn no longer rebuilds the sidebar, the first switch after launch is a view change, and the link graph builds off the frame.

## Added

- **A pane's own settings over the control surface.** `new-pane` takes a `settings` object (so a media pane, code viewer or wiki pane is built already pointed at its file or vault) and the new `pane-set` applies the same object to a live pane; `gpty pane-settings` lists the keys. There is one closed vocabulary, `PaneTypes.sanitize_settings`, at a third source, `SOURCE_IPC`, so a `pane-set` and a saved tile cannot describe the same key differently. The values that are not a caller's to set - the pane's identity and geometry, the user's own env and Inspector aim, and the wiki's restore-only gestures - refuse over the socket; the call is all-or-nothing (any refused key answers `-32602` naming every one and applies nothing), a `vault_path` change over an unsaved note answers `-32000`, and the answer is the pane read back (`changed` names the keys whose value moved, `settings` is the tile document) rather than an echo of the request. Neither verb writes the user-owned stores: `pane-set --setting vault_path=…` shows a vault in a pane, it does not register one for the socket's vault verbs.
- **The wiki pane's view state has a verb.** `gpty pane-view <pane> [--graph] [--note <path>] [--mode edit|split|preview]` is one verb for the three gestures the toolbar offered, applied note then mode then graph so `--note index.md --graph` selects the note the graph's Back returns to. It is display-only and focus-free - it never activates the pane - and the answer reads the pane back (`graph`, `note`, `view_mode`), so `--graph` fails rather than reports success when the canvas did not come up.
- **A pane moves to another workspace instead of closing.** Workspaces are live parallel grids, so a move is a reparent: the PTY, scrollback and pane env are keyed by `attachment_id` and stay put, and `PaneBody.backend_preserved` keeps a `cli_view`, media or Inspector backend alive across the `_exit_tree` a reparent fires. A terminal moves with its follow set (today the Reasoning pane); a follower moved alone is warned that it will observe nothing.
- **The sidebar's three sections fold.** Workspaces, Profiles and Panes each get one header builder - heading label, the section's add button where it has one, then the fold toggle as the header's right-most control - so Panes gains a real header row instead of a bare label. A fold hides the list and drops the section's combined minimum to its header, an update while folded cannot re-open it, and the state persists per section in `user://settings.json` (`sidebar_folded`), so folding Profiles to reach Panes survives a relaunch. Tests: `godot/tests/integration/test_sidebar.gd` covers the fold, the update-while-folded case, the glyph/tooltip swap and the section-id whitelist.
- **Two scroll chevrons on every scrolling pane.** `ScrollHints` drives a pane's own scroller through one of three bindings - a `ScrollBar`, a `Tree`, or the terminal grid - and each chevron shows only while its direction has content, so a body that fits its viewport shows neither. The terminal gains the top chevron (jump to the oldest line: one `scroll_up(get_history_size())`, ~79 µs at 102x78 regardless of scrollback depth) beside the bottom one that returns to live output. Wired: code viewer, CLI view, the Inspector's answer, the Reasoning turn list, both halves of the wiki note view, and the file tree; media and the link graph are exempt by design.
- **The Inspector's backend is a dropdown.** Pane Settings builds it from `GptyAi.list_backends()` on every open, and the vocabulary lives in one pure module (`godot/scenes/panes/backend_choice.gd`) that mirrors `BackendKind::parse`, so a profile that names an alias (`oh-my-pi`, `pi`) selects the canonical row and re-saves its kind. A program the machine does not have stays listed and selectable, labelled `(not found)` with the install-or-`GPTY_OMP` sentence; a value the list does not know becomes `Custom: <value>` instead of being reset.

## Changed

- **A one-row change repaints one row.** `TerminalPane`'s paint is split across a background band and a text band per row plus an overlay for the focus border, cursor, scrollback indicator, selection and search highlights. A partial grid update queues only the rows its damage covers, and a blink, selection or search change queues the overlay alone. Measured on the release gdext: one-row damage 2286 → 190 µs at 102x78 (120x60: 2286 → 120 µs), a cursor blink 0-3 µs over idle, and the `BENCH_FLOOD=1` full repaint still 3262 → 2957 µs; the render is pixel-identical (`ui-capture --compare` reports identical PNGs).
- **A streaming pane follows the frame cadence.** The work budget is a share of the wall clock (~24% at any cadence), and a sync that fits its share relaxes the back-off instead of parking at the 10 Hz ceiling - the branch a streaming child never reached because it always had damage. Measured with `draw_bench --max-fps 60`: 10.5-13.3 → 33.5-39.5 syncs/s at 102x78, 16.5-23.2 → 34.6-39.5 at 120x60. Tests: `test_a_sync_that_fits_the_stretched_window_relaxes_the_cadence` and `test_the_same_cost_still_stretches_at_the_frame_cadence`.
- **A spawn no longer rebuilds the sidebar.** `_sync_pane_rows` mutates the pane list in place: a closed row is detached in the same call, a spawn builds only its own row, a renumbered label is rewritten on its row, and a row's actions swap for its check/cross in place. Creating a pane no longer pays the recorded 7-10.4 ms per row (five Phosphor glyph Labels) for every row already on screen - the growth that made a spawn at 64 panes rebuild 64 rows.
- **A workspace switch skips the sidebar's rebuild.** The three lists are rebuilt only when their content changed, so a switch no longer spends the measured 62 of 74 ms on five workspace rows (7 ms each), two profile rows (7 ms) and the pane rows (10.4 ms), against 0.1 ms of pane settings.
- **The first switch after launch is a view change.** `_prime_restored_workspaces` lays out and starts one restored workspace per frame after the launch frame instead of on its first arrival frame: the arriving workspace's started panes go 0/1 → 1/1, the arrival frame 29.4 → 4.4 ms and switch-to-first-sync 49.5 → 18.5 ms, so the first switch is 0.53-0.58x a warm one. Consequences worth knowing: every restored workspace's programs now start at launch, a saved pane whose program cannot start warns and closes its tile then rather than on first visit, and closing a never-visited workspace asks the running-work question because its programs are live. Tests: `test_a_restored_workspace_starts_its_panes_before_it_is_viewed`, `test_priming_does_not_restart_a_running_child`.
- **The link graph builds off the frame.** The Rust `vault_graph` query, the model parse and the layout run in one `WorkerThreadPool` task; `_poll_graph_build` applies the landed result, a build that is no longer wanted or that read a previous vault is dropped, a wanted graph whose build read the wrong root is rebuilt, and `graph_built(ok, reason)` reports it once. `pane-view --graph` therefore answers late with the real state instead of freezing the window for the build, and a drag survives a re-query.
- **The pane menu names its actions.** The More menu is three named actions - Minimize/Restore pane, Swap pane, Switch pane type - and Switch opens a second popup listing every type with its icon and the current one checked, so a type press reads as the destructive rebuild it is. Workspace rows and pane menus build their items through `MenuItems.add`/`MenuItems.add_radio`, one icon+text+tooltip path.
- **The README's memory-cost chart is generated from a ledger.** `docs/data/cost-history.json` holds one measured point per release from v0.1.0 (the pre-harness releases measured from their shipped Linux archives by `scripts/backfill-cost-history`), `scripts/render-cost-chart` draws `docs/static/images/cost-history.svg` from it, and each release's own row is recorded with `scripts/measure-cost --record` - so the picture cannot drift from the numbers.

## Fixed

- **Opening Settings with a non-terminal first tile empties the Concepts section.** `Workspace.get_terminal_for_ffi` walked every tile reading `_terminal`, which a Reasoning pane does not have, so the function aborted and answered null even when a terminal sat in another tile; the walk now answers only a `TerminalPane`'s live backend. Tests: `test_workspace_concept_terminal.gd`.
- **The workspace store keeps its grid unit.** `PaneTypes` owns the unit vocabulary (`GRID`, `GRID_LEGACY`, `sanitize_grid_unit`), save and load round-trip the field, and an unknown unit is stored as "infer" rather than a number this build cannot scale; a store written in a coarser unit restores the same shares.
- **Every launch no longer prints two engine errors.** `A11y` queues role and value writes and applies them from the host's `NOTIFICATION_ACCESSIBILITY_UPDATE`, the only place Godot 4.7.2 accepts `update_set_role`/`update_set_value` (it refuses them outside that notification), instead of calling the server at the call site.
- **A restored terminal publishes its text to the AT-SPI tree.** The value push follows the screen text, limited only by `A11Y_PUSH_MS` - it was gated on a settle window keyed to the grid's damage counter, which a restored or busy pane never satisfied - the publish host is re-resolved on every push, and the node's text travels in the channel the AT-SPI adapter actually reads.
- **Small windows adapt instead of clipping.** `OverlayPanel.fit_card` clamps the Settings and Pane Settings cards to the window (shared with the command palette), so the 540×560 card is 540×484 at 800×500 and 540×324 at 560×340 instead of hanging past the bottom edge; pane titles stop before the button column and ellipsize with the full title on the tooltip; the sidebar scrolls as one column so every row is reachable at 800×500; and `UiTokens.MIN_LAYOUT` drops from 540×560 to 560×340.
- **Resizing a pane is smooth.** Four defects in one row: the resize cursor recovers because the click that starts a divider drag no longer swallows its own release (`TileDrag` publishes the drag's axis and the workspace sets the default cursor); a terminal fills itself with the grid's own background so a drag shows no grey band; and a release no longer hops the divider.
- **A toast burst shows every message in turn.** `_enqueue` appends instead of dismissing the visible toast, the toast's own tween callback starts the next, and the queue is bounded at eight (oldest dropped, newest kept) so a caller in a loop cannot grow it. Tests: `test_a_second_message_waits_for_the_first`, `test_the_dismissal_starts_the_queued_message`, `test_the_queue_is_bounded_and_keeps_the_newest`.
- **A concept row's provenance tooltip shows.** The provenance had two owners - the row's `HBox` and the `Label` inside it, whose tooltip could never appear because a `Label` ignores the mouse by default; the label now owns it with `MOUSE_FILTER_STOP`. The audit found two more unreachable tooltips (the Terminal tab's on-disk size and the concept editor's error list) and fixed them the same way.
- **The File Tree's first double-click opens the folder.** Population is the first expand (`_populate`, then `collapsed = false`), because a new `TreeItem` starts expanded and the old handler flipped that to collapsed in the same event; later activations still toggle. Test: `test_file_tree.gd::test_the_first_activation_expands_a_folder`.
- **The OMP event channel is not capped at four events a second.** The extension's one-connection-per-event client wrote its request, half-closed, and never read the answer, so every event sat out the full 250 ms timeout: reasoning deltas outran the channel by ~15x, the outbox dropped the oldest chunks, and `omp.agent.settled` sat behind the backlog. `socket.resume?.()` at connect takes the answer off the wire and keeps the channel fire-and-forget: ~4 800 events/s on Node and 5 769/s on Bun. Test: `test/extension.test.js` "takes the answer off the wire so a connection can finish". A running OMP keeps the module it loaded, so restart the session to pick up the extension change.
