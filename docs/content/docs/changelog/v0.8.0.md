[Release on GitHub](https://github.com/godot-pty/gpty/compare/v0.7.2...v0.8.0)

The interface is the release this time. v0.8.0 re-baselines the October 2026 UI audit on a fresh build and commits the harness that takes its evidence, then lays the foundation the rest of the 0.8 chain builds on: one theme built from one token module, a light palette that follows the desktop, a UI scale that cannot push the layout under itself, and screen-reader accessibility as a surface the app maintains rather than a flag someone else set. The chrome stops being mouse-only along the way - pane buttons, the Wiki pane and the vault link graph are all reachable from the keyboard, and an overlay that is open now actually owns the keyboard.

Nothing in the PTY engine, the IPC surface or the control API changes behaviour in this release.

## Added

- **A committed UI capture harness, and the re-baselined audit that used it.** `godot/tests/bench/ui_capture.gd` stages 21 named states through the real main scene and autoloads - first launch, the sidebar, Settings, Pane Settings, the palette, the file picker, an empty workspace, the UI scale at 125 % in two window sizes, the light theme in two states, three window sizes, the wiki vault, the link graph, the concept editor, plugin review, Save Profile, workspace trust and the agent badges - and writes `<out>/<state>.png` from the app's own viewport. `scripts/ui-capture` drives it (`--list` prints the table, `--audit-focus <state>` prints what keyboard traversal can reach: the focus owner, the dialog's own focus owner, whether Escape closes the surface, every visible `FOCUS_NONE` button, the Tab order and every keyboard ring), and `scripts/ui-capture-check` proves a state's capture is *local* to that state - a perturbed capture must differ, or the state is showing something it does not own. All of it runs under `scripts/ui-sandbox`, which creates one owner-only temp root and exports a private `HOME`, `XDG_*`, `GPTY_TEST_USER_DIR` and `GPTY_SOCKET` with `GPTY_SECRET`, `BASH_ENV`, `ENV`, `PS1` and `HISTFILE` cleared, so a capture never depends on the developer's desktop and a running GUI cannot claim the socket. Re-running the audit's own method on a 0.7.2 build found all nine findings still open; the rows that followed closed them.
- **One design system: a token module, a built theme and a UI scale.** `godot/scenes/ui/ui_tokens.gd` is the single owner of the chrome's numbers that do not change with the mode - a 7-step type scale (11/12/13/14/16/18/36), a 7-step spacing scale, one 3 px corner radius, the 22×18 px floor every icon button takes, and `contrast_ratio()`, the WCAG maths `UiPalette.CONTRAST_PAIRS` is graded by so a colour choice is measurable rather than argued. `godot/scenes/ui/ui_theme.gd` builds the one `Theme` from it (`Window`, `AcceptDialog` with `ConfirmationDialog` by class fallback, `GraphEdit`/`GraphNode`, tabs, popups, inputs, lists, scrollbars, tooltips, separators) and `Workspace._ready()` applies it on the scene root, so every pane, overlay, popup and dialog inherits it. Settings → Appearance gained a **UI scale** picker. Measured on the launch screen: Close All is `DANGER` at 6.75:1 on the sidebar, where it was 3.49:1, and the status bar's right-hand readout is 6.35:1, where it was 4.15:1.
- **A light theme, and an `Appearance: follow system` mode.** `godot/scenes/ui/ui_palette.gd` is now the colour owner: two complete sets (`DARK` and `LIGHT`, 18 tokens each), with the five terminal-facing entries equal in both because they are drawn over the terminal's own scheme. `cfg_appearance_mode` selects dark, light or system, and system resolves through the engine's theme-change callback, so flipping the desktop's dark mode re-themes gPTY without a restart. Every read site is `UiPalette.active()` at draw time - the old `const`s are gone, so a cached copy cannot compile - and 14 token-carrying `add_theme_color_override` sites became four `Theme` type variations (`MutedLabel`, `DangerLabel`, `WarningLabel`, `AccentButton`) plus a palette-read status-bar surface.
- **Screen-reader accessibility as a product surface.** `godot/scenes/ui/accessibility.gd` (`A11y`) is the owner: `enabled()` reports whether a driver is loaded or a reader says it is attached, `set_text` records the visible text and pushes it as the element value, `publish(host, slot, text, live)` maintains a hidden text node per pane so terminal output is announced as a live region, and `announce_host` returns a tile's title bar. Names are enforced at the choke point - `Icons.icon_button` requires the words as an argument, so a glyph button cannot be built unnamed - and `scripts/accessibility-probe` proves they reach an assistive technology: it emulates a screen reader on the session bus, launches the app with the AccessKit driver, walks the AT-SPI registry and asserts the controls this repo named are in the tree.
- **The colour-override census is a gate, not a convention.** `scripts/check-theme-tokens` scans `godot/scenes/**/*.gd` and fails a `add_theme_color_override` call or a `UiPalette.active()` read that happens at class-body level - field and `const` initializers, `@export` defaults, inner-class fields, class-level lambdas - decided by an indentation stack that a `func` opener interrupts, so an in-function read (the correct per-call read) passes. `# theme-ok: <why>` on the line or within the three above is the reviewed exception, the way `// log-ok:` works. It runs as step 3.3 of `scripts/ci-check`, and the light theme could not have landed without it.
- **One icon-button treatment for the whole chrome.** `Icons.icon_button(btn, glyph, accessible_name, variation)` applies `UiTheme.ICON_BUTTON`, floors the control at `UiTokens.BUTTON_MIN_WIDTH`/`BUTTON_MIN_HEIGHT` - one target shared with the sidebar - and draws the codepoint in a child `Label`, which also stops the engine composing `"<name>: <codepoint>"` into the exposed accessible name. Every icon button in the chrome is built by it now (the pane title bars, the sidebar, the window controls, the file picker's header). At rest a glyph button is the glyph on an empty stylebox; hover and press tint it with the accent; focus draws the 1 px accent ring. Text buttons (Settings, Close All) keep the filled base, because an icon and its word are one control.
- **The file picker wears the app's own frame.** `AppDialog.picker(parent, title, file_mode, access)` builds every `FileDialog`: borderless, the engine title band hidden, and a header of its own - a title `Label` and an `Icons.CLOSE` button wired to the engine's cancel button, so `canceled` and a site's `queue_free` behave exactly like Cancel - inserted above the engine's own path bar, list and button row. All four sites migrated (workspace directory, terminal font and scheme, Settings font).
- **The keyboard drives pane chrome, the Wiki pane and the vault link graph.** The five title-bar buttons of every pane are `FOCUS_ALL` with an explicit ring (`TerminalManager._wire_chrome_keyboard`), the note toolbar (Edit/Split/Preview, Rename, Delete, Save) is a ring of its own reachable while the buffer keeps focus, and the graph canvas with its three actions is a fourth ring - the canvas first, drawing its own accent focus frame because a custom-drawn `Control` has no stylebox to do it. Arrows pan, `+`/`-` zoom about the crosshair, Enter opens the note under it, Escape leaves the canvas. Measured with `--audit-focus` on the `wiki-vault` state: 3 components, 1 closed ring, 83 of 83 focusable controls reached, where the old walk printed 5.
- **Project files and policies.** `CODE_OF_CONDUCT.md`, `CONTRIBUTING.md`, `SECURITY.md`, `SUPPORT.md`, `GOVERNANCE.md`, `MAINTAINERS.md`, `.github/CODEOWNERS`, issue and pull-request templates, and the DCO trailer now enforced by `githooks/commit-msg`.
- **The docs home and README show one clip per feature.** `scripts/record-demo` records each feature section separately (panes, wiki, media, streaming panes, agents, concepts), and the site plays the matching clip in place, with the README collapsing each into a `<details>` block so the text stays scannable.

## Changed

- **Every dialog is built by one builder.** `godot/scenes/ui/app_dialog.gd` (`AppDialog.confirm`/`alert`/`set_body`/`body_of`/`group_buttons`) constructs and parents all 19 `ConfirmationDialog`/`AcceptDialog` sites. Buttons group at the right edge - Restore and Cancel sat about 290 px apart in a 1046 px dialog before, 8 px after - and text the user must read and may need to copy moved to a read-only `TextEdit` body, so a path containing `[b]` cannot be read as markup.
- **An empty workspace says what it is and what opens it.** The viewport clear colour is `UiTokens.BG` instead of Godot's default `rgb(76,76,76)`, and a mouse-transparent empty state shows "No panes" and "Ctrl+Shift+N opens a terminal" - the second line formats the binding from `PaneTypes.ALL["terminal"]["shortcut"]`, so the hint cannot drift from the key. It appears exactly when the active workspace has no tiles and leaves on the next spawn.
- **Settings, Pane Settings and the concept editor are opaque.** `Panel`, `PanelContainer`, `PopupPanel`, `AcceptDialog` and the editor's `GraphEdit` take an opaque `SURFACE` with a 1 px border, and `Tree`/`ItemList` take an opaque content background, so no pane text or Add Pane grid shows through a card. The Pane Settings `Attachment ID` field gained the sentence it was missing: the id IPC, MCP and agent commands address the pane by.
- **The vault graph places labels instead of drawing them.** `VaultGraphView.label_placements` orders the candidates by what the user is aiming at (crosshair, pointer, open note), then degree, then id, and `VaultGraphModel.cull_labels` drops a box that would print over one already accepted - so the note identity at the highest-degree centre survives the bundled vault's 52 notes and 267 links.
- **The README states the project's posture.** Badges are grouped by what they claim, the Linux Foundation registration and the current Scorecard link are both there, and the demo GIFs collapse behind their summaries.
- **Dependency updates arrive in grouped pull requests**, and `gpty-gdext` uses the `getrandom` 0.4 fill API the new version requires.

## Fixed

- **A UI scale above 100 % can no longer push the layout under its own minimum.** At 800×500 a 125 % request lays the interface out in 640×400, under the Settings card's 540×560. The fix caps the applied scale rather than reflowing: `UiTokens.MIN_LAYOUT` and `UiTokens.ui_scale_ceiling()` (`-1` when the window cannot be measured) feed `SettingsManager.capped_ui_scale_percent()`, and the picker says which percentage the window is actually showing when the cap bites.
- **Window controls never swap maximize for restore.** The glyph is read from `cfg_window_mode` through the shared icon-button treatment: fullscreen shows the restore glyph and "Restore window", every other mode the maximize glyph and "Maximize window".
- **The agent-state badge spells its state with a shape, not a hue.** `failed` and `needs-attention` used to be the same circle and differ only by red against amber. They are now an X-circle and a warning triangle, each with its own accessible name and tooltip, so a protan or deutan user reads the state from the silhouette and a screen reader reads it at all.
- **A stacked overlay never hands the keyboard back to the pane.** The four overlays (Settings, Pane Settings, the palette, the concept editor) extend `OverlayPanel`, which takes focus on open, returns it on close and keeps the Escape contract in one place; with an overlay open, typing reaches the overlay instead of the shell behind it.
- **A stacked overlay no longer lets a global chord act behind it.** `ShortcutManager` registers each chord with `survives_overlay`, and only the palette, the sidebar toggle and the two fullscreen toggles do - every other chord (spawns, close, pane-chrome and note-toolbar focus, reset, workspace switching) is refused and the event consumed, so a chord cannot reach a pane underneath a dialog.
- **An unchanged accessible line no longer takes the reader's node.** `A11y.publish` returns an unchanged slot as it is, so the once-a-second republish of the same terminal line no longer replaces the element a reader is on; a changed line in a live region still replaces it.
- **The capture harness cannot hang, and a failed staging says so.** Each `ui-capture` launch is bounded (`CAPTURE_TIMEOUT`), a state that cannot stage reports immediately instead of waiting out the run, `ui-capture-check`'s perturb state defaults to a state in the requested list (so a single new state can be checked), and the `file-dialog` capture is byte-identical between runs.
- **A release capture no longer hangs on a backend that cannot grab.** `scripts/screenshot-gpty` preferred ffmpeg's `x11grab -window_id`, which can attach to nothing and print nothing; the call also sat bare under `set -e`, so the guard that bounded it aborted the script instead of letting the fallback run. The backends are now a list tried under `CAPTURE_TIMEOUT` (`SCREENSHOT_TIMEOUT`, default 20 s), a failing or timed-out one hands over to the next, `SCREENSHOT_CAPTURE=ffmpeg|import` pins one, and the failure names every backend tried.
