[Release on GitHub](https://github.com/godot-pty/gpty/compare/v0.8.0...v0.8.1)

The second step of the 0.8 chain is the chrome a user touches every minute, and the surfaces that already existed but never said what they were. A pane's title bar is three controls and one action menu instead of five buttons; the command palette lists every pane type and action with its own glyph and its own chord and answers the arrow keys; a saved command can be inserted or run straight from it; and the Add Pane grid, every pane type and the About tab each explain themselves through one help table. The terminal pane gained a return-to-live-output chevron, a search strip that no longer covers the prompt, a visible scrollbar on every scrollable surface, and a child that is born at the size it is drawn at instead of 80×24.

Under that, two stores stop being a dead end: a `history.db` or `vaults.db` SQLite cannot read is moved aside and replaced, where before every pane warned on every launch and no scrollback was ever persisted again. The IPC surface gets one stated refusal rule (`-32602` for a bad value, `-32000` for app state), `new-pane --command` and `cli_view` stop answering success over a program that never started, and an outbound link that the OS refuses now reports itself instead of failing silently. The PTY engine's only behavioural change is the size a child is born at.

## Added

- **Every pane bar is three controls and one action menu.** The title bar carries **Pane settings**, **More actions** and **Close**, so the type list no longer costs a button - the bar reserves 74 px where it reserved 122, and a 180 px sidebar leaves its pane label the room to be read. `TerminalManager.show_pane_actions_popup` is the one place a pane's actions are defined: minimize/restore (the label follows the pane's state), swap position (disabled while a single tile has nothing to swap with), and the eight pane types as radio-check items with the current one marked. The sidebar's pane row opens the same builder, so the two surfaces cannot list different actions, and choosing the current type is a no-op instead of a same-type rebuild. Pane content is inset now, and the code viewer paints the shared empty state instead of a blank body.
- **The command palette is populated, ranked and honest.** `Ctrl+Shift+P` lists all 15 entries at once - one per pane type, the six actions, and **Save Command…** - in a 560×480 card centred on the workspace instead of a 320×160 panel whose top-left corner sat on the workspace centre, and clamps to 528×308 at the 560×340 layout floor instead of hanging outside its host. Every row shows words rather than the command id, the registry's own glyph and the chord read from the binding registry (`ShortcutManager.chord(action)`), so a rebinding cannot leave a stale hint; the keyboard cursor is the palette's `SELECTED_ROW` treatment, moved by Up/Down and activating on Enter.
- **A saved command is a first-class object, and the palette runs it.** `SavedCommandStore` (`user://commands.json`, `{commands: [{name, command, run}]}`) is the one place a saved command lives: at most 200 entries, a 64-character name and a 1024-character command, LF/CR/TAB folded to one space with every other control dropped, names compared case-insensitively, and `add`/`update`/`remove`/`move` the only writers - a profile, layout, plugin or IPC call has no path in. The seventh Settings tab (**Commands**) edits the list, and the palette inserts the command line at the pane's prompt or runs it (through `PaneTypes.shell_run_args`) depending on the entry's flag.
- **The Add Pane grid, every pane type and the About tab explain themselves.** The grid stays glyph-only and names itself three ways: its header names the tile under the pointer, falls back to the tile the keyboard cursor is on, and reverts to `Add Pane:` when both leave. The same header carries the section's **Help** button, whose press opens an `AppDialog` table of **glyph / action / chord** for all eight pane types, and About lists every shortcut on the same data (`shortcut_catalog.gd`), so a chord cannot appear in one place and not the other. `SectionHelp.attach()` is one generic module, so the workspace, profile and pane headers can adopt it without a second implementation.
- **Feedback is a built-in path to a prefilled issue.** **Feedback** is the fourth sidebar footer action, directly below **Close All**, and it opens `github.com/godot-pty/gpty/issues/new` with three prompts - what happened, what was expected, steps to reproduce - and an "About this build" block carrying the app version, the OS and the renderer. The text is one pure module (`FeedbackText`), so the wording is testable without a scene tree.
- **The search strip moved off the prompt, and a toast is readable.** The strip is one opaque raised panel anchored to the pane's **top** edge (6 px inset, 36 px tall), so it covers the two oldest visible rows instead of the prompt and the live output; the scrollback indicator moves to row 2.5 while it is open instead of drawing underneath. Its right-hand end reads `n/m` (`0/m` before the first jump, `Invalid pattern` in the danger colour with the engine's own sentence in the tooltip - the old error string was set and never shown), and the step buttons are its own glyph controls. Toasts are legible against every pane surface, and an appearance swatch says its reading (opacity, "unset", or the colour) in a tooltip that has a real hover target.
- **A scrolled-back pane returns to live output in one click.** `TerminalPane` carries a floating chevron (24×24, bottom-right, tooltip and accessible name **Return to live output**) shown exactly while the scroll offset is above zero. The sync sits on every path that moves the view - the wheel, PageUp/PageDown, typing, a click, a search jump - rather than only in the frame sync, which left the control up to a sync interval stale after a wheel.
- **The window bar and the view panes' toolbars are keyboard rings.** The three titlebar controls are focusable and joined into one explicit ring, entered by `Ctrl+Shift+A` and left by Escape, and the chord is inert in **System Frame** mode where the bar is hidden. The two view panes' toolbars are rings entered by `Ctrl+Shift+L`: the contract moved onto `PaneBody` (`_action_bar`, `focus_toolbar()`, `toolbar_has_focus()`, `leave_toolbar()`), so a third view pane joins by assigning one field instead of re-implementing the traversal.
- **Every scrollable surface has a scrollbar.** The track and focus boxes were empty styleboxes and the grabbers were margin-less flats, so every `ScrollContainer` reserved a 0 px column, drew nothing and could not be dragged - a wheel was the only way to learn a tab continues. `UiTokens` now owns the geometry (`SCROLLBAR_THICKNESS` 8, `SCROLLBAR_INSET` 1, `SCROLLBAR_MIN_THUMB` 24) and the theme derives every bar from it, so the affordance is visible and draggable everywhere a list, a tab or a pane scrolls.
- **Every outbound link reports a refusal.** `ExternalLink` is the only path from an in-app URL to the OS: on anything but `OK` it copies the fallback text and raises a 6 s warning naming the URL (the toast's copy shortened to 120 characters, the clipboard's whole). All four sites use it - the Feedback row, the plugin catalogue, the About links and the File Tree's confirmed open - where before a refused handler was dropped by a seam typed to return nothing.
- **The capture harness audits an open overlay.** `--audit-focus` snapshots the open overlay's visible, enabled `FOCUS_NONE` buttons - text, tooltip and declared reason - before the Escape that closes it, reports each as `mouse-only button scope=overlay`, and splits the summary into `declared` and `unaccounted`, so a control that is mouse-only on purpose is distinguishable from one that was forgotten.

## Changed

- **The IPC surface gives a bad value and app state different codes.** The split was real and no rule decided it: 14 refusal rows answered `-32000` where the request's own value was the problem. The rule is stated once on two constructors - `bad_param` (`-32602`, a value the caller can fix) and `app_state` (`-32000`, the app cannot answer now) - and every pane-API arm uses one of them.
- **A close or reset confirmation names the workspace and the pane.** With `lazygit` running in the `git` workspace's T1, closing asked "Closing will stop processes still running in: T1" - the label alone names neither the workspace nor what T1 is. A workspace-scoped action now names the workspace in the intro, and every dialog qualifies the pane (`T1 (git)`), so the sentence identifies the thing the user is about to stop.
- **ShortcutManager owns the terminal's chords.** The terminal pane's bindings were literal key comparisons in `_gui_input`; they are registered actions now, so the About list, the palette's hints and the actual handling read one registry.
- **The fuzz workspace's lockfile is audited like the main one.** `ci-check` fails when the fuzz lockfile drifts from its manifest, so the nightly harness cannot build against dependencies the gate never looked at.
- **The README's badge block claims what it can evidence.** Badges are grouped by what they assert, the platform badge is simplified, and the link to the current Scorecard report is kept.

## Fixed

- **A damaged history store is no longer a dead end.** A `user://history.db` whose pages carry b-tree type bytes and no SQLite header - 56,938,496 bytes in the reported case, unrecoverable even by `sqlite3 .recover` - made every restored pane warn on every launch and no scrollback was ever persisted again. The shared store plumbing now moves an unreadable file aside as `history.db.corrupt` and recreates the schema, so the app continues with an empty scrollback history and says so once, instead of failing forever.
- **A damaged vault index recovers the same way.** `VaultStore::open` had the shape `HistoryStore::open` had and none of the recovery, so a damaged `vaults.db` left the Wiki pane's note list, search, link graph and backlinks dead with `vault index unavailable: file is not a database`. It now replaces the file (`vaults.db.corrupt`) and rebuilds the index, and the six call sites share that path.
- **A fresh pane's child starts at the size the pane is drawn at.** The pty was opened at portable-pty's 24×80 and resized 50 ms later, so a child's own first read reported 80×24 whatever the grid said. The pty is opened with `PtySize { rows, cols }` taken from one fitted-grid helper - the same threshold the resize debounce uses - so a child is born at the size the debounce would settle on, and the debounce never resizes a child by its own creation.
- **`pane-read --lines N` no longer spends the limit on screen padding.** `TermGrid::plain_text` now drops trailing empty rows before applying the limit, so a small N returns the program's last lines instead of a tail of blanks. Leading and interior blanks stay - a blank row inside output is content - and the grid walk is still byte-exact.
- **`new-pane --command` runs the line instead of failing to spawn it.** `command` on a terminal is a command line run through the configured shell (`-c`, `/c` for `cmd.exe`), the shape `paneRun` already used, so the pane's program is the user's shell and the line is its argument. Before, `echo hi` was executed as a program name and the call answered a pane whose `pid` was null.
- **`new-pane -t cli_view` refuses a program that cannot start.** The pane answered a successful document for `/nonexistent/...`, `pane-read` was empty and `pane-status` said `no status primitives` - the refusal was only in the pane's own label. The pane keeps `start_error()`, and the IPC arm answers `-32000 cannot stat executable …` with no pane left behind.
- **`conceptToggle` no longer invents a concept.** The arm passed the caller's name straight to the toggle, whose not-found branch appended `{name, enabled}` to the user store, so one IPC call per unknown name grew `user://concepts.json` without bound and `conceptList` reported the phantom rows. A name the merged set does not hold now answers `-32602 Unknown concept: <name>` and writes nothing.
- **`layoutSave` answers the name the store kept.** The arm answered the requested name while the store de-duplicated to `name (2)`, so a script that saved twice under one name believed both answers addressed its profile and a load silently resolved the first. `add_profile` returns the stored name and the arm answers that; the sidebar's save toast says the de-duplicated name too.
- **The `working` badge reads as a state, not a dim dot.** At 12 px it was one thin arc (`SPINNER_GAP`) whose stroke was mostly partial coverage, measured at 11.7 ink pixels against 23.9-26.5 for `completed`, `failed` and `needs-attention`. `AgentBadge` now owns the state table and paints `working` as a 1.75 px band with a turning notch; all four states draw at 16 px and read 48-58 ink pixels, distinct with the hue removed.
- **The File Tree says why it has nothing to show.** An unlistable root used to render an empty `Tree`. It now paints the pane's shared empty state, one sentence per case - **No folder open** (repeating the bad value), **Not a folder**, **Folder not found**, **Cannot list this folder** - and a folder that really is empty keeps its own sentence, which also says hidden entries are not listed. Every hint names the resolved path and where the fix is.
- **The History search results are keyboard-operable.** Each hit is a focusable toggle with the palette's selected treatment, `Up`/`Down` from the field move the cursor instead of reaching the child as an arrow sequence, and `Enter` copies the cursor's line through the one click path - so the toast names the row the keyboard was on.
- **The CLI's version-probe latch is keyed by endpoint.** One process-wide `AtomicBool` let a concurrently running test silence the probe, so `cargo test` failed with `probes == 0` on an unrelated file. The latch is now a list of endpoints, and production's one endpoint behaves as before.
- **A manager/drag pair is freed instead of leaked at exit.** `TerminalManager` and the divider-drag state machine were held by a reference cycle; the tree now drops them with the workspace.
- **The unreachable NUL guard is gone.** It could not fire - a Godot `String` cannot hold a NUL, measured - and it printed a unicode error when it did, so it was removed rather than left as a branch nobody can reach.
- **Back-to-back docs pushes no longer fail the Docs deploy.** Two causes, one per failure: a newer run was refused with "in progress deployment" (400), and a deploy could read the artifact list after `upload-pages-artifact` finalised and answer "Found 0 artifact(s)" with no other run alive. A workflow-level concurrency group queues the runs, the deploy moved into its own job so `gh run rerun --failed` cannot upload a second artifact, and a bounded wait polls the run's artifact list before deploying.
- **The MCP registry publish job no longer executes the released tag with its OIDC identity.** The job holds `id-token: write` and publishes under the project's name, yet it checked out the release's tag and ran `scripts/mcp-registry check` from that tree (code scanning alert 13). It now runs only default-branch code and reads `server.json` and the crate manifest through the contents API into a temporary descriptor directory, so a tag push cannot turn into code run under that identity.
- **The capture harness no longer approves a plan the trust state exists to review.** It recorded every tile a state seeds as approved, which silenced the `workspace-trust` state itself - the one state whose whole point is the prompt.
