[Release on GitHub](https://github.com/godot-pty/gpty/compare/v0.8.5...v0.8.6)

v0.8.6 is the differentiator release: the interface stops looking like a generic Godot app. Every effect is a setting - off, subtle or full - and display-only: terminal shader effects, pane transitions under one Motion switch, and concept-driven cues that flash the pane a concept matched. The vault graph becomes a physical 3D map, the terminal gains imported colour schemes and follows the chrome's light/dark choice, the window can be truly translucent, and the engine's default splash is replaced by a branded frame. The renderer bake-off kept Forward+ as the default and documented Compatibility as the 2.2x-lighter opt-in.

## Added

- **Terminal effects are a closed table.** `Settings -> Appearance -> Effects` offers `CRT scanlines` and `Film grain` and an `Off`/`Subtle`/`Full` intensity, Off by default; Subtle halves the shader's amplitude. CRT is static scanlines, a phosphor mask and a vignette whose scanline period comes from the pane's own height and the font's cell height, never from the screen resolution, with a lit band and a dark gap so it reads on both themes. Grain renders into a half-resolution `SubViewport` at 30 Hz. The table is closed: its two `preload` paths are the only shaders the app can run, the pane schema accepts only its ids, and a test keeps the two lists equal. A pane paints its ground through one effect quad under every band, so text, selection, inverse cells and ANSI backgrounds stay opaque; a static effect is not evaluated per frame. The choice persists as `effect`/`effect_intensity` and reaches every terminal without a restart.

- **Panes animate, under one Motion setting.** `Settings -> Appearance -> Motion` is a master switch - Off, Subtle or Full - plus one picker per transition and the selected animation's own property rows. Off draws every change in one frame, Subtle eases with no overshoot, and Full allows the animation's declared overshoot capped at 3 %. The registry is the only implementation: each entry declares the transitions it serves (create/close/swap), the channels it touches and a property schema, so a new animation appears in the pickers with no settings or workspace code. A create reserves the final rect first, then fades and scales its wrapper from 0.92 with the pivot at the centre, so no sibling moves; a close detaches the tile, grows the siblings, draws the dying wrapper above them and below the divider bands, fades it out and frees it exactly once; a position swap records both rects, commits the tile data, lays out, then eases both wrappers between them. A layout pass snaps create and swap to final and leaves a close ghost alone, and the launch/profile restore path never animates. Transitions are skipped on a hidden or inactive workspace, during a divider drag, and while a terminal in that workspace is under flood load.

- **The transition library grows to slide, pop and crossfade.** Slide offsets a wrapper toward the tile's split edge by 8-240 px (default 48) and then eases it to the final rect; the manager records which edge a tile was split from (`left`/`right`/`top`/`bottom`) and the runner clamps the offset to the grid, so a ghost never paints over the sidebar. Pop grows from 0.55 in 120 ms on the existing alpha+scale channels. Crossfade dissolves both swap wrappers out where they were drawn, trades their rects at the midpoint and dissolves them back in. Every entry keeps the framework's contract: Off/None is one frame, a natural finish lands exactly on the final rect, scale and alpha, and a second transition on the same wrapper takes ownership of the first. The pickers and property rows took no change - all three appear from their registry entry alone.

- **Reactive environments.** `Settings -> Appearance -> Effects -> Reactive effects` maps a concept to a cue: Off, Tint (red), Pulse (accent) or Particles (green), with at most eight rules and none by default. The trigger is the existing concept drain: a routed capture and a notify-only notice both ask the source pane to cue, and nothing is acknowledged, flushed or published back into the engine - the cue is display-only. A pane cues at most once per 334 ms (three starts in any second; a trigger inside the window is dropped, not queued), and a hidden pane never cues, so an off-screen workspace pays no GPU work. Tint is a 16 %-peak wash (80 ms in, 240 ms hold, 400 ms out), Pulse a 2 px border at 0.9 fading over 500 ms, and Particles a 48-particle burst whose pool is allocated once and re-emitted with `restart()`. No cue is full-screen; the pane is the surface.

- **The vault graph is a physical 3D map you can push around.** The graph is a `SubViewport` holding a `RigidBody3D` per note and one spring per drawn edge, with a deterministic per-id depth layer. A drag freezes one body, pushes its neighbours and rewrites its incident rest lengths on release, so the map settles when you let go; the simulation freezes when it is settled or hidden, and the at-rest map skips a pointless settle pass. Node positions ride the pane's layout state, capped at 4000 entries, rounded to 0.1 and ignored per missing note; the graph data, link resolution and semantic hit-test stay in `VaultGraphModel`, on camera-projected screen positions rather than a physics raycast. The cinematic layer is additive/alpha halos, depth fog that leaves the ground alone, dark-theme glow, a fixed-seed dust pool only while moving, and a vignette; glow is enabled only on Forward+. The planar canvas remains the fallback; `graph_mode` is auto/3d/2d, and auto picks the orbital map on any hardware adapter (Compatibility included) and the planar canvas only on a software rasterizer, superseding the v0.8.5 rule that Compatibility resolved to planar. An explicit choice wins on every renderer, and switching modes keeps the arrangement.

- **Colour schemes import, and the terminal follows the chrome's light/dark choice.** `gpty-core::scheme` turns a native JSON, Alacritty (TOML and YAML), iTerm2 XML plist, Base16 or legacy 16-colour CSV file into one complete scheme - 16 ANSI entries plus foreground, background, cursor and selection - capped at 16 KiB, with a closed native key set, a strict YAML block-mapping subset, and an iTerm2 reader that refuses an internal DOCTYPE subset, CDATA and any entity but the five predefined ones. An imported native file is copied into `user://schemes/`, so the source may move or be deleted. Eleven schemes ship: dracula, gruvbox dark/light, nord, tokyo-night, catppuccin mocha/latte, one-light, solarized dark/light and vivid. The terminal now joins the chrome's existing resolution: `scheme_dark`/`scheme_light` are read through one accessor, an empty light slot follows the dark one, and the old `color_scheme` key migrates on load; a pane can still keep its own scheme, and the chrome palette stays separate. Colour reaches the cells for real - the palette carries the default foreground/background pair, the cell reader resolves the default named colours through it, and the palette is applied unconditionally after the shell starts.

- **Window opacity and terminal padding.** `Settings -> System -> Window opacity` (presets 100/95/90/85/80/75/70/60/50/40 %, clamped 40-100) makes the whole window genuinely translucent through one full-screen veil that samples the finished canvas, renormalises its premultiplied colour and writes the setting's alpha once - an in-app capture of the 70 % setting reads framebuffer alpha 0.698, where a per-surface `modulate` read 0.992. The row is present on every display server and disabled with a reason where the window cannot be transparent, so the shipped feature never looks unshipped. `Settings -> Appearance -> Terminal padding` (0-24 px per side, default 4) is spent on the fit: the row and column counts always equal what the pane draws, and a padding or font-size change refits the live grid instead of waiting for a tile resize.

- **The empty workspace teaches every shortcut.** The Getting Started guide replaces the two-label empty state: a title and subtitle, a 3 s keycap press that cycles the four spawn chords, an **Open a Terminal** action, and all 23 registered bindings as grouped cards read from the shortcut registry. The guide re-reads the registry on every show, keeps the action above the fold, scrolls inside the empty surface at 560x340, centres when it fits, and gives the hero keycap the keyboard on a zero-pane first run.

- **The launch frame is gPTY's own.** `godot/assets/boot_splash.png` is a committed 3840x2160 frame - the icon's blue line art, a 640 px mark and a 240 px Open Sans SemiBold wordmark over a soft accent glow on the dark surface `#202128`, 172 KiB. `project.godot` names it, pins `bg_color` to the same colour so every letterbox or crop edge is seamless, and keeps the width on stretch so a 4:3 window letterboxes without clipping the mark and a wider window crops only the flat edge. The engine's Godot logo is gone on all three platforms.

- **About reads the README and everything it links.** The About tab is a documentation viewer over a generated `godot/docs.json`: the Markdown reachable from `README.md` - the root guides, the roadmap, the changelog and the agents pages - packed with a byte-for-byte `--check`. The generator strips YAML front matter, unwraps `<details>`/`<summary>` and drops the README's badge header; every internal link, relative or GitHub blob URL, becomes a `gpty-doc:` key matched against the bundle (1024-byte cap, bundled keys only, so the shell is never handed a scheme). Navigation is a capped history - 64 entries, a new page truncates the forward tail, overflow drops the second entry - so Back always reaches the README. The keyboard shortcuts moved to their own Shortcuts tab, and the app and IPC versions share one row.

## Changed

- **`main` is the development trunk, and a release is a pull request.** Feature work lands on `main` through the merge queue; a `release/vX.Y` branch is maintenance-only, created from the line's last tag when development moves to the next minor, and the 0.8 line stays active through 0.8.7. A release is a short-lived `release-prep/vX.Y.Z` branch against `main`, and the active line tags the merge result. CI now gates pull-request jobs by the paths they touch, merges the Windows jobs, adds the cost bench, and pins the fuzz nightly, so a docs-only change no longer pays for the whole runtime suite.

- **The release build is warmed from one shared workflow.** `release-build.yml` is the single build definition a tag and a `workflow_dispatch` share. A tag run only restores caches - an entry it saved would be tag-scoped and unreadable by the next tag - while the Linux FFmpeg prefix is image-scoped (22.04 for the bundle's glibc floor, 24.04 for CI) and release-profile target caches stay apart from the debug ones.

- **The wiki pane's chrome is one view at a time.** A new pane opens on the graph. The note list shows Graph, the note editor shows Notes and Graph, and the graph shows Notes; the top-level action reads **New**; one Planar/Orbital button switches the map, and Relayout resets and fits. The duplicate Fit button and the Physical button are gone, and switching modes keeps the arrangement.

- **Forward+ stays the default; Compatibility is the documented opt-in.** The bake-off ran the same build on both renderers. On the shipped v0.8.5 build, Forward+ is 667 MB warm with one pane (669 with eight, 1083 on a first launch) and Compatibility is 310 (305 with eight, 363 on a first launch) - 2.2x lighter warm and 3x lighter on a first launch. Mobile measured 592 with one pane and was rejected as only 11 % below Forward+. `draw_bench` found no material repaint penalty (1.60/3.39 ms on Forward+ against 1.48/3.72 ms on Compatibility at 90x30/200x60), while the 4K effect bench still cannot isolate a shader (a 0-13 us delta) and stays in v0.9. `project.godot` now pins `forward_plus` explicitly, and `--rendering-driver opengl3` is the documented opt-in.

## Fixed

- **A pane's font-size setting reaches text already on screen.** The `PaneBody.font_size` setter now re-applies the size to every view the type owns - the Inspector's answer and thinking views, the CLI view, the code editor, rendered Markdown and empty states, the file tree's `Tree` (which had never received it), the media pane's placeholder and status - invalidates any height measured at the old font, tolerates null widgets (a spawn applies settings before `_ready`), and refits the grid. A repeated value is a no-op, so the debounced panel does not re-measure per keystroke.

- **A file read is always bounded.** `TextRead` used `get_size` to decide truncation and then read a whole file when the stat reported zero or a writer appended after it, so `/proc`-style dynamic files and concurrent writes could be read uncapped on the GUI thread. It now reads at most cap+1 bytes through `get_buffer`, closes immediately after, never calls `get_as_text`, reports the size it actually read, and shows a truncation notice when the cap was hit.

- **Spawn validation judges the right owner, on Windows too.** Three copies of the owner check assumed host UID semantics, so a spawn refused an owner the kernel reports as `/proc/sys/fs/overflowuid` while `geteuid()` is the user. One rule now answers "may this file run": absolute, regular, not group/other-writable, owned by this user, root, or the overflow UID only where that UID is outside `/proc/self/uid_map` - an unreadable `/proc` fails closed - and saved paths also walk their ancestors for writability. A Windows absolute program path such as `C:\Tools\app.exe` is now stat'ed instead of being waved through as a bare name.

- **A settings save repaints only what changed, once.** `TerminalPane.apply_settings` always ended in a full repaint, so saving `history_lines` or `shell_env` repainted every row of every terminal in every workspace, and an appearance change ran the same loop twice. It now snapshots the draw-read keys before and after the shared assignment and repaints only when one moved: a non-visual save repaints zero, a font-size change repaints once, and an appearance change repaints zero because the palette tokens it reads are identical in both sets.

- **The Reasoning pane re-wraps when it narrows.** The pane pinned every turn view's minimum width to the width its height was last measured at, and the container propagated that floor, so a 420 -> 220 px resize left the view at 400 px and autowrap never ran. The view's laid-out width now comes from its container and only its height is assigned; a resize re-measures at the new width, and the height cache is invalidated on a font-size change, which also reaches existing turns.

- **The Settings card keeps one size across all eight tabs.** The card was content-sized per tab, so every switch re-laid out the header, the tab bar and the rows under the pointer and moved the centred overlay. One `CARD_SIZE` of 720x640 now serves every tab, clamped to the 560x400 floor, and `tab_changed` no longer relayouts.

- **The Settings tab bar fits the 560 px floor.** At the floor the live eight-tab bar needed 561 px of the 504 it had and hid `Shortcuts` and `About`. Cause: a `TabContainer` takes its tab styleboxes and font colours from the `TabContainer` theme item, not the `TabBar` item, so the engine's default 20 px-per-tab box was live and both off-brand and 57 px too wide. Both types now carry the same boxes and colours, the engine's 8 px `side_margin` is zeroed, and the eight tabs occupy 497 of 512 px with no arrows.

- **A workspace switch repaints the settled orbital graph.** Leaving the wiki workspace and returning drew the previous map as a static background: the pause path disabled the viewport and the only code that re-enabled it ran from a physics frame that is off while the map is settled. The visible branch now clears the paused flag and requests one frame when settled.

- **The default graph build carries the keyboard off the list it replaces.** `_show_graph_canvas` reads the focus owner before hiding anything and hands the keyboard to the canvas only when that owner is a surface the canvas replaces - the list, search, note box/toolbar, footer, placeholder, New and Graph. The decision is read at land time instead of remembered, so a press whose build lands after the user clicked another pane no longer steals focus.

- **A software rasterizer is named, and the FPS reads as its cost.** When no GPU context exists, Godot falls back from Vulkan to OpenGL to a CPU rasterizer and the app used to print a bare `80 FPS` as if it were the app's cost. `RendererInfo` now matches llvmpipe, softpipe, SwiftShader, WARP and Apple's software renderer, writes one `[renderer]` line naming the driver, method, adapter, viewport, device scale, screen refresh, vsync, frame cap and effect, and warns once that the frame rate is CPU-bound and to check the driver (the Linux kernel-module sentence is gated to Linux). The status bar appends ` · software` to the FPS and `Settings -> About` carries a `Renderer:` line. Windows ships the full chain - Vulkan, then D3D12/WARP, then native OpenGL 3, then the statically linked ANGLE - and the 3D graph enables glow only on Forward+.

- **The test harness refuses to delete outside its sandbox.** A fixture helper that removed a path it had been given could be handed an empty string, a relative path, a filesystem root or the user-data root and recursively delete the working tree. `TestPaths.is_safe_user_path`/`remove_tree` now strictly validate an absolute path inside the test user directory and refuse empty or whitespace, relative paths, virtual schemes, roots and the user-dir root itself; seven unsafe local copies were replaced, with a unit suite for the guard.

- **The GUT gate finishes a run a runtime error broke.** `scripts/gut-check` treated every `SCRIPT ERROR` as an abort, so one out-of-bounds read ended Godot and the rest of the suite never ran. It now aborts only when a script or parse error appears before the first test - the collector or autoload failure - and otherwise lets the run finish, splitting the verdict into "not trustworthy" (a killed run, no Run Summary, a collection failure) versus a named failure. The Windows GUT failures that exposed this were fixture paths and dialog indexes, fixed by isolating each test's fixtures.

- **Two gate tests stop asserting the machine.** The motion tests awaited a fixed wall-clock delay against a 200 ms tween, so a stalled frame expired the timer and the tween together and the next line read a freed ghost; they now poll `PaneTransitions.playing()` to its end state and sample ghosts only while valid. The PTY input-queue test asserted how much the kernel's tty buffers would swallow; it now saturates the writer queue deterministically and fails on the queue bound, not the kernel's appetite.

- **`docs-check` ignores scratch markdown.** Ignored `TEMP/` scratch - blog drafts and forensics baselines - was walked by the gate, so a draft with repo-relative links turned every commit red. `TEMP/` now joins the gate's skip prefixes, matching what `.gitignore` already excluded.

- **The release and CI gates stop lying.** `server.json` must carry both version fields; `install-rust` handles an empty target array on macOS bash; the installed Godot is exposed as `godot` on `PATH`; the gate requires the four CodeQL analysis jobs on merge groups, fails when GitHub abandons a job, and keeps a pull request's macOS proof when the queue abandons its runner.
