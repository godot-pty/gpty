## Added

- **Each workspace has a working directory.** A workspace carries its own default directory, new panes start there, the pane's `PWD` stays in step with it, and the workspace's directory button shows a folder instead of a bare label. The directory is part of the trust decision for what a workspace's panes may open, so it is bound where the workspace is chosen rather than read from whichever shell reports last.
- **The Inspector pane remembers what you aimed it at.** The prompt and the switches are saved per pane (`user://pane_inspector.json`, keyed by the pane's attachment id) and restored on the next start; closing the pane discards the stored aim instead of leaving it to land on whatever takes that slot. Both stay app-owned runtime state: a layout or profile file still cannot set them.
- **A sidebar profile row opens a new workspace.** Aside from activating the profile in the current workspace, the row can open it in a fresh one, which is what the profile catalog was for.
- **`new-pane --split <side>` places the new pane where you asked.** `left`, `right`, `top` and `bottom` are honoured; when the grid cannot honour a side it falls back to the larger-axis split instead of failing.
- **The vault verbs answer only for a vault you have opened.** `vault search`, `vault read` and `vault weight` (and their MCP tools) serve a root registered by opening that vault in a Wiki pane's settings, and a refused root says it is not registered and how to fix it. Before this, the socket would index any path the caller named.
- **The knowledge base ships in the release bundle.** `godot/knowledge.json` is packed with the app, so a release install has the wiki without a source checkout.
- **gPTY's own processes harden themselves against environment reads.** On Linux the GUI and the CLI set `PR_SET_DUMPABLE 0`, which makes `/proc/<pid>/environ` and `/proc/<pid>/maps` unreadable to a program in a pane; on Windows both install a process DACL that withholds memory-read and thread-injection rights while keeping the peer-check and terminate masks the control socket uses. `GPTY_SECRET` now gates pane programs on both platforms.
- **The MCP entry is published from the release.** `server.json` is the descriptor, `ci-check` refuses a version that disagrees with the CLI crate, and `.github/workflows/mcp-registry.yml` publishes it over OIDC when a release is published - no secret, and no hand-published entry that drifts from the binary.

## Changed

- **A release is three downloads, not thirty-six.** The platform archives already contain the GDExtension and the pinned FFmpeg set, so publishing those libraries again made the Releases page a build-artifact dump and inflated the project's only install signal (v0.7.0's "73 downloads" were 7 real bundles). A release is now the three archives plus `SHA256SUMS`, and the checksum, attestation and upload lists cannot disagree about the asset set.
- **A window holds at most 96 live panes.** Counted across every workspace, because a hidden workspace's pane keeps its PTY, child process and grid. `new-pane`/`pane-run` past the ceiling answer with the limit instead of starting another process, and a layout or profile with more tiles restores what fits and says how many did not.
- **One IPC connection serves a batch.** A client that writes several newline-framed requests gets one answer per request, in order, and a bad frame costs that frame rather than the rest of the pipeline. The shipped clients still use one connection per call, so this adds a guarantee rather than moving a caller.
- **A refusal reaches the caller as its own sentence.** A handler's `{code, message}` travels flat to the CLI and to MCP - `error: rpc error -32000: Pane 'x' not found` - instead of a stringified JSON envelope, and an MCP tool that refuses is a successful response carrying `isError: true` with that sentence rather than a protocol error. The unused `gpty-ipc` typed request models are gone, so the handlers' `params.get(...)` keys are the wire vocabulary and `wire.rs` is the one place a renamed argument is translated.
- **Stores and logs are owner-only and content-free.** A store written by an older build is repaired to 0600 when it is next read (`O_NOFOLLOW`, `fstat` on the descriptor, `fchmod` only a looser mode of a file this user owns), the user directory is kept at 0700, and log files at 0600. An agent backend's stderr is sanitized, bounded, logged at `debug` and shown in the failure message instead of reaching the console at `warn`.
- **A file-supplied pane cannot name a resource to load.** Pane settings are a closed per-type table (`PaneTypes.settings_schema`) with a range or format per key, the restore path drops the keys only the app may set, and terminal fonts load from bytes so a font path never reaches `load()`.
- **A profile's trust comes from where it came from, not what it claims.** `ProfileManager` stamps each entry's origin, user entries are stripped of the fields that claim provenance, and the consent walk is chosen by that stamp - a `profiles.json` entry cannot borrow a builtin's name or a plugin's id.
- **The CLI prints the cause chain when a command fails.** An error that ends in `moving … into …` now says what the move answered.
- **Documentation-only pushes skip the code CI, and the local gate classifies too.** `scripts/ci-check` judges the pushed range (docs-only gets the docs gates, everything else the full suite, `--fast` the index, `CI_CHECK_FULL=1` forces everything), the pre-push hook runs it before the ref moves, and `ci.yml` ignores docs-only paths while the Docs workflow becomes their gate. The CI jobs also cache what they actually rebuild - the FFmpeg prefix above all - which is what made the Windows vcpkg rebuild stop landing in a job cap. CodeQL runs on pull requests and weekly instead of every push.

## Fixed

- **A selection stays on its text.** A bare `Ctrl` or `Shift` no longer snaps a scrolled-back pane to the bottom, so `Ctrl+Shift+C` copies scrollback; the selection follows its text when the view scrolls (wheel, PageUp/PageDown, a search jump) and when output arrives, instead of holding a fixed screen row; copy reads grid rows, so a selection scrolled out of view still copies in full; wrapped lines copy joined instead of gaining a newline at each wrap; and the selection is dropped when the width changes or an app switches to the alternate screen, which is alacritty's rule - the old highlight survived and landed on different text.
- **A paste cannot close its own bracketed-paste bracket.** Pasted text drops the control characters that could end the bracket early (and `DEL`), on both the bracketed and the plain branch; the filter is one cached PCRE2 pass, because the per-character loop it replaced took 34.8 s for 1 MiB where the pass takes 6 ms.
- **A pane cannot grow the GUI by opening an escape string and never closing it.** The grid's parser bounds an unterminated OSC at 64 KiB and closes it, which is the same bound the line parser already applied; before this, a pane printing `ESC ] 0 ;` and an endless payload took the GUI from 3.3 MB to 260 MB in 1 MiB steps. On Windows ConPTY buffers the string itself before gPTY sees a byte, and the smoke's step now proves the difference rather than claiming it.
- **A media seek no longer freezes the window.** A seek claims a serial, queues the command and returns instead of waiting for an acknowledgement with a 5 s deadline, so a file that keeps the decoder inside a libavcodec call can no longer stall the Godot thread once per slider step - measured at 1 µs where the old path returned an error after 5 s. The pane is told nothing from the replaced timeline is presentable until the worker applies the seek.
- **A media open cannot hang, and cannot be redirected.** The open reads a verified descriptor (`O_NONBLOCK | O_NOFOLLOW`, `fstat`-checked) and hands FFmpeg a custom `AVIOContext`, so a FIFO swapped in after the path check never blocks `open(2)`; the interrupt callback's leak is gone; a frame that would resample past the size cap is refused as `too_large` before it is allocated; and closing a pane no longer waits forever on a decoder - the join is bounded at 2 s, after which the worker is detached and frees its own contexts.
- **`first_pipe_instance` is claimed only when a create succeeds.** A transient failure on the Windows pipe used to spend the claim, so every later instance was non-first and a process racing for the name could own it - the restarted GUI then attached to that process instead of refusing. The claim is now recorded on success, and the `rust-windows` job runs the test that drives the sequence.
- **A fresh plugin install completes.** The destination's parent (`plugins/<owner>/`) is created before the rename, the review's acceptance now actually moves content, and the printed failure carries the underlying cause instead of only the two paths.
- **A profile accent stays in its workspace.** Each workspace records its own activated profile, so activating one in workspace 1 no longer highlights it in workspace 2; a new workspace starts with none and switching back restores that tab's own.
- **An agent's events stay in their workspace, and a renamed terminal keeps its companion.** Agent events are fanned out by terminal session id and attachment id inside their own workspace, so two workspaces running the same profile no longer cross their Reasoning panes, and renaming a terminal rewrites the companion's `source_attachment_id` instead of leaving it subscribed to an id that no longer exists.
- **A pane label two workspaces share is refused.** `inject`, `paneRead`, `paneStatus` and `killPane` resolve an `attachment_id` first; a label resolves only when exactly one pane carries it, and an ambiguous label is refused with the ids to re-address.
- **Scrollback's last line survives a pane close.** The writer re-drains a closed queue before breaking, and `PaneHistory::drop` joins the writer instead of returning early - the parallel test run that had been losing the last line is now deterministic.
- **A vault walk and a vault read stay inside the vault.** Symlinks and junctions are resolved and kept only when they canonicalize inside the canonical root; a skipped link is counted and shown in the pane's footer, and a second road to the same file no longer bypasses the check.
- **A plugin command checks the binary it is about to talk to.** The stale-binary probe runs before the `plugin` arm dispatches, so a newer CLI against an older GUI (and the reverse) says so instead of reporting a corrupt store.
- **The Inspector pane's prompt is runtime-only.** `system_prompt`, `auto_run` and `accept_concept_captures` are `file: false`, so a restored layout or a profile cannot preconfigure a pane to submit captured output under a file-chosen prompt, and `auto_run` defaults off.
- **Closing a terminal whose child outlived its I/O task asks first.** That pane used to read as idle, so closing it killed the surviving process group without a question.
- **The Inspector backend's stdout is read through one bounded frame reader**, so a long or split frame is no longer misparsed as several.
- **The bundled agent skill is inside the CLI crate**, so `gpty --skill` works from an installed crate as well as from the repository.
