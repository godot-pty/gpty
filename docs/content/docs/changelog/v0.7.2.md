[Release on GitHub](https://github.com/godot-pty/gpty/compare/v0.7.1...v0.7.2)

Three runtime fixes lead this release: the shipped Knowledge Base profile opens again, a Godot virtual path is no longer accepted where a real filesystem path is required, and the media pane stops retaining its read buffer per open. Everything else is build, CI and repository hygiene with no behaviour change for a running app - it is what a reader acting on this project (forking it, auditing it, or building it) will notice, and what the October 2026 security audit's build-and-CI half added.

## Added

- **A fuzz harness for every parser that reads attacker-controlled bytes.** `fuzz/` is its own workspace with seven cargo-fuzz targets: `grid_feed` (the terminal grid), `line_parser` (capture-side line parsing), `ipc_request` (newline framing plus JSON-RPC decoding), `vault_links` (wikilink parsing and target resolution), `markdown` (both renderers), `ai_frame` (the Inspector's frame reader) and `media_probe` (the FFmpeg probe). Twenty-three named seeds are committed from the byte strings the existing tests use. `ci.yml` builds every target on each pull request, and `fuzz.yml` runs each for five minutes nightly and on dispatch, uploading artifacts on failure. The harness paid for itself in its first ten seconds: `media_probe` found the read-buffer leak fixed below.
- **A dependency policy, not just an advisory check.** `deny.toml` is enforced by a `cargo deny check` step in `ci-check` and its own CI job. It allows only crates.io as a source (no git or path dependencies), permits the licences the dependency graph actually uses plus the project's own GPL-3.0-or-later, denies yanked crates, and warns on duplicate versions - so a licence the release cannot ship fails a build instead of a review.
- **OpenSSF Scorecard runs weekly.** `.github/workflows/scorecard.yml` runs the pinned Scorecard action on a weekly schedule, on every push to `main`, on a branch-protection change and on dispatch; it publishes SARIF through the same action the CodeQL job uses, posts the result to the public API and keeps the raw report as an artifact. The first baseline: **7.7 overall**, with Branch-Protection 6/10 (from 0 before this release's rulesets).
- **Dependency updates arrive as grouped pull requests.** `.github/dependabot.yml` opens one weekly pull request per ecosystem - the workspace's cargo tree, the fuzz workspace's own lockfile, and GitHub Actions. Actions are pinned to commit SHAs for supply-chain reasons, so without this they would never move.
- **The docs gate resolves the code citations inside roadmap rows.** `scripts/docs-check` extracts every backticked `path:line` evidence token from a roadmap row and checks that the file exists (a repo path, or a basename that names exactly one file), failing with the fix spelled out when it is missing or ambiguous. A row whose proof was deleted by a rename no longer stays green.

## Changed

- **`unsafe` is fenced by the compiler.** `gpty-core`, `gpty-ipc`, `gpty-ai`, `gpty-gdext` and `gpty-media` deny `unsafe_op_in_unsafe_fn` and `clippy::undocumented_unsafe_blocks`; the CLI forbids unsafe code outside tests. The five crates' existing blocks each state their invariant now (28 had no comment), and `cargo clippy --workspace --all-targets -- -D warnings` is clean.
- **Every crate's Windows test build is checked locally, not only in CI.** The local cross-check runs with `--tests`, which is what CI's native Windows job runs too. The first run exposed three test-only Windows breakages that had never been compiled.
- **The `v*` tag ruleset makes signed tags the release procedure.** The release workflow holds `contents: write`, `id-token: write` and `attestations: write`, and a tag push starts it - so the ruleset blocks tag creation, update and deletion for everyone but an organization admin, rejects non-fast-forward pushes, and requires a signed tag. Releases are tagged with `git tag -s` and verified with `git tag -v` before the tag is pushed.
- **`main` is protected.** A pull request with one approving review is required, force-pushes and deletion are blocked, commits must be signed, conversations must be resolved, and status checks run in strict mode. Admin enforcement stays off: the maintainer's direct push is the documented trunk-based bypass until required checks are filled in.
- **The MCP registry entry publishes itself.** `mcp-registry.yml` used to trigger on `release: published`, which GitHub never starts for an event the release workflow's own `GITHUB_TOKEN` produced - so every previous entry was a manual step. It now triggers on the Release workflow's successful completion, which the tag push started, and `server.json` remains the descriptor.
- **A documentation-only change runs the docs gates and nothing else.** `ci.yml` ignores docs-only paths, and the local gate detects the same set and runs just `docs-check` plus the knowledge-bundle check. The Docs workflow now verifies `godot/knowledge.json` too, so a stale bundle can no longer reach `main` with CI green.
- **CI stops rebuilding what it already built.** The Windows build and check jobs use separate cache keys (a check-shaped target can never satisfy a `cargo build`), and the pinned FFmpeg prefix - about two minutes of work per job - is cached for both Rust jobs, with `media-deps`'s stamp still deciding whether the cache is usable.
- **A gate run leaves nothing behind in the temporary directory.** Every test that binds a socket or builds a store creates it inside a `tempfile::TempDir` bound to the test body, so it is removed on success and on panic, and `ci-check` fails when a new `gpty-*` entry survives the suite.
- **The README and the docs site state the project's actual posture.** The README carries the OpenSSF Best Practices badge (now **passing**) and **SLSA Build Level 2** - the level artifact attestations claim on their own - linking to a new "Verifying releases" section with the `gh attestation verify` instructions. The docs site's theme favicon set is replaced by the app icon (ICO, PNG, SVG, Apple touch, Android, web manifest), and the navbar gains a Reddit icon next to GitHub; the Docs workflow's paths now include `assets/site-icons/**`, so an icon-only change rebuilds the site that consumes it.

## Fixed

- **The shipped Knowledge Base profile opens again.** The profile seeded its 52 bundled notes and then listed nothing: `KnowledgeStore` globalized its root only when Godot said the path was not absolute, and Godot 4.7 answers `true` for `user://` - so the scheme was handed to the vault index, whose Rust path gate refused it as "not an absolute path". `BasePersistenceManager` now has one vocabulary for paths that leave Godot: `is_virtual_path()`, `real_path()` and `is_real_absolute_path()`, and the store resolves its root to a real directory. A `res://` or `user://` value is no longer accepted anywhere a real filesystem path is required.
- **A media probe no longer leaks its read buffer.** Each open leaked 32 KiB (8 MB over 1000 opens measured through VmRSS, 6 MB for a valid WAV). FFmpeg's `avio_context_free` frees the context but never a caller-supplied buffer, and `ffio_ensure_seekback` may replace that buffer - so `Avio::drop` now frees the pointer current at drop time, after the context. 2000 instrumented opens of the crafted input report no leak or double free, and 1000 plain opens hold VmRSS flat.
- **The audit gate is clean against the current advisory database.** `pulldown-cmark` 0.13.6 closes RUSTSEC-2026-0433 (quadratic parsing of nested image wikilinks); the renderer never enables the wikilink extension, so the app was not reachable through it, but the audit gate denies warnings and no release could pass with the advisory present.
- **`gut-check` ends a run at the first script error, and a stalled run fails early with the test that stalled.** The gate launches Godot itself and watches the log: a parse or script error aborts the run immediately instead of waiting for the timeout, and the deadline escalates from `SIGTERM` to `SIGKILL` because Godot does not die on `SIGTERM` while a script is waiting. A run that produces no output for two minutes is a hang rather than a slow test - the suite starts a test every ~0.15 s and the longest single test waits 2.1 s - so it is stopped there, and the failure names the last test started, its script and the command to re-run just that file. A hung suite no longer occupies a runner until the job cap with nothing to attribute it to.
