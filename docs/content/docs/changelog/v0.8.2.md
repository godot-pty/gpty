[Release on GitHub](https://github.com/godot-pty/gpty/compare/v0.8.1...v0.8.2)

This is the release daily use wrote. Closing a workspace or a pane is an explicit action on the thing itself instead of a footer button, an empty workspace is a guide that teaches every registered shortcut, and the shipped layouts are ordinary profiles that can be deleted - as can every installed plugin profile, from its own row. A first run can now honestly hold zero workspaces and zero panes, and the first pane created there makes a **Default** workspace.

Under the surface it closes the defects the last week of use turned up: a workspace switch that cost about a second is 40 ms, an emptied workspace stays empty across a restart, a spawned pane takes the keyboard, closing a pane activates the survivor instead of the oldest tile, a dialog cannot grow past the window it opens in, and a keystroke into a streaming pane is no longer held at the 10 Hz back-off ceiling. The status bar also stops printing the pane's fetch/draw milliseconds; the FPS reading stays.

## Added

- **The empty workspace is a guide that teaches every shortcut.** The two-label empty state is replaced by `ShortcutGuide`: a **Getting Started** title and subtitle, a keycap that presses itself every 3 s and cycles the four spawn bindings, and all 23 registered bindings as grouped cards read from `ShortcutCatalog` on every show. The keycap is the action - pressing it starts the pane the current step names, so the separate button and subtitle are gone - and the guide keeps the action above the fold and scrolls inside the surface at 560×340. Tests: `test_shortcut_guide.gd` covers the rows, the cycle, the action and the pin, and the first-launch and floor states carry committed captures.
- **Workspace and pane close is explicit, and the last workspace can be closed.** The sidebar's footer **Close All** is gone: the **Workspaces** and **Panes** title rows and every workspace and pane row first swap their actions for an inline check/cross, then run the existing running-work and unsaved-edit walk. A workspace row's folder button is a **More** menu with **Set Directory** (the current path is its tooltip) and **Clear Workspace**, which empties a hidden workspace without switching to it, and the trash glyph now means discard everywhere - row close buttons, the pane title bar and the palette's close-active entry. Closing the last workspace is legal: first run and "close all workspaces" land on zero workspaces with the guide, the first pane created there creates a **Default** workspace, a profile activated with no workspace creates it too, and the store round-trips the zero state.
- **The shipped layouts are ordinary profiles, and every profile can be removed.** `Agent Workspace` and `Knowledge Base` are copied into `user://profiles.json` once (`seeded_defaults`), so they are deletable and renameable like any saved profile and a deleted copy stays deleted. Installed plugin profiles gain a trash that asks with the same check/cross and calls the new `GptyTerminal.uninstall_plugin()`; the plugin store and its uninstall API moved into a shared `gpty-plugin` crate so the GUI and `gpty plugin uninstall` cannot drift. Saving, renaming or installing into a same-named user profile asks first, and save/rename replace through `ProfileManager` while an install applies the replacement only after the plugin record lands. No delete-all was added to the Profiles header.
- **The workspace switch has a bench that measures the real path.** `godot/tests/bench/switch_bench.gd` is the windowed complement to `draw_bench.gd`: it switches between two workspaces, settles each incoming pane until its grid generation stops changing so the focus-triggered a11y publish is actually exercised, and reports the switch, the first painted frame, and the pane's own fetch/draw/back-off numbers.

## Changed

- **The status bar shows FPS only.** The right-hand label no longer appends the focused pane's fetch/draw milliseconds; it reads `FPS | clock | version`. The pane keeps `_fetch_ms`/`_draw_ms` for the flood back-off and the benches, and the timings join the diagnostics pane planned for v0.9. `test_right_label_carries_no_ms_readout` pins the removal.
- **A sidebar row returns to itself when a rename changes nothing.** The inline rename editor is torn down on every commit path, so submitting the same name - or pressing Escape - restores the label instead of leaving a right-aligned editor behind. **Rename Workspace** joins the row's **More** menu and reuses the open editor, and every text-bearing sidebar button is built through `_make_sidebar_button`, which centers row labels and icon+text actions while keeping the label clip so a long user-authored name cannot stretch the 164 px section.
- **A saved empty workspace is a real state.** The pre-workspaces `layout.json` import now runs only when the store file is missing (`has_store()`), so a close-all that persisted `workspaces: []` is no longer rewritten into a terminal on the next launch.

## Fixed

- **A workspace switch no longer costs about a second.** Three costs compounded: `_switch_workspace` re-applied settings, appearance, FPS and window mode on every switch; focusing the incoming pane published its whole visible screen as a `Label`'s shaped text (17 315 characters cost 992 ms in one call); and the first painted frame waited on both. A switch is a view change now, `WindowChrome.apply_mode` returns early on the mode it already applied, the a11y content is carried in `accessibility_name` alone (the channel the AT-SPI adapter actually reads) and an unchanged slot stays put. Measured against the reporter's own store with `btop` in both panes: switch 992-1,020 ms → 40.6 ms, first painted frame 1.5-1.6 s → 78 ms, the publish 992 308 µs → 53 µs. `switch_bench.gd` records it.
- **An emptied workspace stays empty, a spawned pane takes the keyboard, and a close activates the survivor.** The one-terminal seed ran for every empty layout, so a layout the user emptied restored a terminal; it now runs only for a first run, and a profile that restores nothing does not invent a terminal either. `_spawn_pane_into(..., activate := true)` is the one activation point, so a new pane - from the sidebar, the palette, `newPane` or a profile - owns the keyboard immediately, while `paneRun` does not steal it. Closing a pane activates the last surviving tile instead of the first terminal, for every pane type, before the sidebar list is rebuilt.
- **A dialog cannot grow past the window it opens in.** `AppDialog` now clamps every modal: `modal_limit`/`popup` centre with `popup_centered_clamped` inside a viewport share, `set_text` gives its autowrap label a width floor (an unfixed one was shaped one word per line before its first layout), `set_body` clamps its minimum, the hidden engine label clips, and all 25 popup sites migrated. The longest text in the app - the running-work list - is captured inside an 800×500 frame in `issue-v0.8.1-running-work-800x500.png`.
- **Typing into a streaming pane is not throttled to 10 Hz.** The flood back-off compared `_fetch_ms + _draw_ms` with the 4 ms per-frame budget once per sync, so a 9 ms sync in a 100 ms window kept re-arming the ceiling and only view input was exempt. Both send helpers now call `_note_view_input`, which zeroes `_sync_backoff` for `VIEW_INPUT_GRACE_MS`, so a keystroke, paste or mouse report reclaims the frame cadence. Measured at the reporter's shape: back-off 93.9 ms → 0.0, 2-3 → 14-19 refreshes per 300 ms, key-to-next-grid-change p50 14.2 ms. `test_typed_input_reclaims_the_frame_cadence` pins it; the cadence-scaled budget and the damaged-row paint remain queued for v0.8.3.
- **Re-applying unchanged settings no longer repacks the grid.** A workspace switch passed `color_scheme_path` into `apply_to_terminal`, whose setter re-applied the stored scheme and bumped the generation even when the palette already was the system default, so the incoming terminal reported `is_full = true` at 5-6 ms although it had produced no output while hidden. The font, scheme and FPS setters now return on an unchanged value, and a settings save broadcasts to every workspace's terminals and title bars instead of a switch doing it.
- **The workspace's `rustix` is 1.1.6 for RUSTSEC-2026-0486.** The advisory marks unwritten bytes as initialized when the xattr functions are handed a zero-length buffer, which is UB reachable from safe code; gPTY never calls those APIs, but `cargo audit --deny warnings` denies the warning, so the lock and the fuzz lock were both advanced to the fixed release.
