[Release on GitHub](https://github.com/godot-pty/gpty/compare/v0.8.4...v0.8.5)

A release-repair patch. v0.8.4's tag could not be pushed at all, and its macOS archive shipped before the FFmpeg alias fix reached the transport. No application behaviour changes.

## Fixed

- **A release tag could not be created at all.** The `tag` ruleset carried GitHub's `creation` rule with no bypass actors, and `creation` restricts ref creation to bypass actors - with none, nobody can create a tag, the administrator included - so `v0.8.4`'s push was rejected with "Cannot create ref due to creations being restricted". `scripts/check-github-settings` asserted the same wrong rule set, so the gate reported OK while the policy it guards made every release impossible. The ruleset now keeps `deletion`, `non_fast_forward`, `update` and `required_signatures` - a tag must be signed and cannot be moved or deleted - and the check compares against exactly that set, so drift in either direction fails.
- **The macOS archive carries one real file per FFmpeg library again.** v0.8.4's zip held three real ~9.29 MB copies of every library (95,698,840 → 96,084,344 bytes against v0.8.3) because `actions/upload-artifact` dereferences symlinks and FFmpeg ships the unversioned `libavcodec.dylib` as a real file that the bundler lipo'd into a second canonical copy. `scripts/bundle-media` now derives each `<name>.<major>.dylib` and `<name>.dylib` alias as a symlink from the canonical `<name>.<major>.<minor>.<patch>.dylib`, and re-derives them after the transported tree lands in the bundle, so the archive is one real file plus two symlinks whichever way the libraries arrive.
